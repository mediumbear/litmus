== The Map and Writing Files

:litmus-dir: src

Tangling gives each file's text and runs, in memory. Two things remain: the map, which keeps the runs for later, and the files, which have to be written without hurting anyone's work.

The map is a text file, `.litmus/map`, in the output directory. It lists every tangled file with a hash of the text that was written, and the runs of that file. It is not committed, and losing it loses nothing, since tangle can always make it again. What it makes possible:

* `litmus where` turns a line of a tangled file back into a line of a document.
* `litmus tangle` can tell a file that tangle wrote from one that someone edited since (T6).
* `litmus tangle` can tell which files it tangled the last time, to report those that are no longer tangled (T5).

The hash of a file is its SHA-256, in lowercase hexadecimal. The standard library does the work.

… hashHex :file: map.zig
[source,zig]
----
/// The SHA-256 of a file's text, in lowercase hexadecimal.
pub fn hashHex(text: []const u8) [Sha256.digest_length * 2]u8 {
    var digest: [Sha256.digest_length]u8 = undefined;
    Sha256.hash(text, &digest, .{});
    return std.fmt.bytesToHex(digest, .lower);
}
----

The map is one `file` line for each file, with the path and the hash, and under it one line for each run, with six fields separated by tabs: the line in the file, the count, the document, the line in the document, the indent, and the excerpt (`:file:` for a file root). Tabs separate the fields, which is why a path may not hold one (C7). The last field is the excerpt's name, which may hold anything but a newline, so the reader takes the rest of the line as the name.

The document is written as a path, and not a number, so the map is readable and stays valid if the documents are reordered.

/// The text of the map for tangled files whose runs refer to `docs`.
pub fn render(arena: Allocator, docs: []const types.Document, files: []const tangle.Tangled) ![]const u8 {
    var out: std.ArrayList(u8) = .empty;
    try out.appendSlice(arena, header ++ "\n");
    for (files) |file| {
        try out.print(arena, "file\t{s}\t{s}\n", .{ file.path, &hashHex(file.text) });
        for (file.runs) |run| {
            try out.print(arena, "{d}\t{d}\t{s}\t{d}\t{d}\t{s}\n", .{ run.line, run.count, docs[run.doc].path, run.doc_line, run.indent, run.excerpt });
        }
    }
    return out.items;
}

`read` checks the header, then reads lines. It rejects a map of another version, and a map that is damaged: a run before any file, a number that is not a number, a hash of the wrong length. The reader is strict because a wrong map misleads in silence.

… read :file: map.zig
[source,zig]
----
pub const ReadError = error{ UnsupportedMap, BadMap } || Allocator.Error;

/// Reads a map. Anything but the first version is rejected.
pub fn read(arena: Allocator, text: []const u8) ReadError!Map {
    var lines = std.mem.splitScalar(u8, text, '\n');
    const first = lines.next() orelse return error.BadMap;
    if (!std.mem.eql(u8, first, header)) return error.UnsupportedMap;

    var files: std.ArrayList(MapFile) = .empty;
    var runs: std.ArrayList(MapRun) = .empty;
    var current: ?MapFile = null;
    while (lines.next()) |line| {
        if (line.len == 0) continue;
        var fields = std.mem.splitScalar(u8, line, '\t');
        const head = fields.next().?;
        if (std.mem.eql(u8, head, "file")) {
            if (current) |*file| {
                file.runs = try runs.toOwnedSlice(arena);
                try files.append(arena, file.*);
            }
            const path = fields.next() orelse return error.BadMap;
            const hash = fields.next() orelse return error.BadMap;
            if (hash.len != Sha256.digest_length * 2 or fields.next() != null) return error.BadMap;
            current = .{ .path = path, .hash = hash, .runs = &.{} };
            continue;
        }
        if (current == null) return error.BadMap;
        const count = fields.next() orelse return error.BadMap;
        const doc = fields.next() orelse return error.BadMap;
        const doc_line = fields.next() orelse return error.BadMap;
        const indent = fields.next() orelse return error.BadMap;
        const excerpt = fields.rest();
        try runs.append(arena, .{
            .line = std.fmt.parseInt(u32, head, 10) catch return error.BadMap,
            .count = std.fmt.parseInt(u32, count, 10) catch return error.BadMap,
            .doc = doc,
            .doc_line = std.fmt.parseInt(u32, doc_line, 10) catch return error.BadMap,
            .indent = std.fmt.parseInt(u32, indent, 10) catch return error.BadMap,
            .excerpt = excerpt,
        });
    }
    if (current) |*file| {
        file.runs = try runs.toOwnedSlice(arena);
        try files.append(arena, file.*);
    }
    return .{ .files = files.items };
}
----

Runs are sorted by line, so the run that holds a line is found by binary search. `where` uses it on the map's runs, and `check` on the runs in memory, which is why it takes any slice of things that have a `line` and a `count`.

… findRun :file: map.zig
[source,zig]
----
/// The run holding `line` of a file, among runs in order; null if none does.
pub fn findRun(runs: anytype, line: u32) ?usize {
    var lo: usize = 0;
    var hi: usize = runs.len;
    while (lo < hi) {
        const mid = lo + (hi - lo) / 2;
        const run = runs[mid];
        if (line < run.line) {
            hi = mid;
        } else if (line >= run.line + run.count) {
            lo = mid + 1;
        } else return mid;
    }
    return null;
}

=== Writing files

`output.zig` is where Litmus touches the user's files, so it is where care matters most. Three rules of the spec are about this:

T4, write only what changed::
A build tool or a file watcher should see a change only when there is one. A file whose text is already right is not touched, not even to renew its time. A file that is written is written whole, under a temporary name, and then renamed over the old one. Nobody ever reads half a file.

T5, never delete::
A file that the last map lists, but that no document tangles now, is reported and left alone. Deleting would be right most of the time, and the wrong time would cost somebody's work.

T6, never overwrite a change tangle did not make::
Before it writes a file that exists, tangle compares the file with the hash the last map recorded. If they differ, someone edited the file since, and the edit is not in the documents yet. Tangle reports it and writes nothing at all, not even the other files, so the state of the files and the map stays consistent. A file that the map does not list is treated the same way, unless its text already equals what tangle would write. This also covers a fresh clone, where the map does not exist yet. `--force` skips the check.

The function that does it all takes an open directory, so the tests can use a temporary one.

… readOrNull :file: output.zig
[source,zig]

pub fn readOrNull(io: Io, arena: Allocator, dir: Dir, path: []const u8) !?[]const u8 {
    return dir.readFileAlloc(io, path, arena, .limited(1 << 30)) catch |err| switch (err) {
        error.FileNotFound => null,
        else => err,
    };
}
----

An executable file (L9) has to be written so that it can run. A file that already has the right text but the wrong permission should only have its permission changed, so these two functions read and compute the permission bits. `isExecutable` looks at the owner's execute bit. `withExecutable` sets or clears all three, giving an execute bit wherever there is a read bit, as `chmod +x` does. On systems with no such bit, which is Windows, they do nothing.

… permissions :file: output.zig
[source,zig]
----
pub fn isExecutable(permissions: File.Permissions) bool {
    if (comptime !File.Permissions.has_executable_bit) return false;
    return permissions.toMode() & 0o100 != 0;
}

fn withExecutable(permissions: File.Permissions, executable: bool) File.Permissions {
    if (comptime !File.Permissions.has_executable_bit) return permissions;
    var mode = permissions.toMode();
    // An executable bit wherever there is a read bit, as `chmod +x` does.
    const x: @TypeOf(mode) = 0o111;
    mode = if (executable) mode | ((mode & 0o444) >> 2) else mode & ~x;
    return File.Permissions.fromMode(mode);
}
----

`writeAtomic` writes a file whole, under a temporary name in the same directory, and renames it over the destination. The directories above the file are made if they are missing. The permissions are those the file should have: the system applies the umask to them, as it does for any new file.

… writeAtomic :file: output.zig
[source,zig]
----
pub fn writeAtomic(io: Io, dir: Dir, path: []const u8, bytes: []const u8, executable: bool) !void {
    var atomic = try dir.createFileAtomic(io, path, .{
        .permissions = if (executable) .executable_file else .default_file,
        .make_path = true,
        .replace = true,
    });
    defer atomic.deinit(io);
    try atomic.file.writeStreamingAll(io, bytes);
    try atomic.replace(io);
}

=== Writing

`write` has five steps. It is long, and each step is a rule of the spec.

First the previous map, if there is one. A map that cannot be read stops the tangle, with the reason, because without it T6 cannot tell the user's edits from tangle's own files. With `--force` the map is thrown away, as it would be if it were lost.

… write, read the previous map :file: output.zig
[source,zig]
----

    previous = map.read(arena, text) catch |err| switch (err) {
        error.OutOfMemory => return error.OutOfMemory,

----

Then T6. Every existing file is read before any file is written. A file is fine if it equals the text tangle would write, or if its hash is the one the map recorded, which means that nobody changed it. Anything else is a conflict. If there is any, the function returns at once and nothing has been written.

… write, look before writing :file: output.zig
[source,zig]
----
// T6: look at every existing file before writing any.
const Existing = struct { text: ?[]const u8 };
const existing = try arena.alloc(Existing, files.len);
var conflicts: std.ArrayList([]const u8) = .empty;
for (files, existing) |file, *slot| {
    slot.text = try readOrNull(io, arena, dir, file.path);
    const text = slot.text orelse continue;
    if (std.mem.eql(u8, text, file.text) or force) continue;
    const recorded = if (previous) |p| p.find(file.path) else null;
    if (recorded == null or !std.mem.eql(u8, recorded.?.hash, &map.hashHex(text))) {
        try conflicts.append(arena, file.path);
    }
}
if (conflicts.items.len > 0) return .{ .conflicts = conflicts.items };

----

Then T4 and L9. A file that has the right text is left alone, except for its executable bit, which is set if it is wrong. Every other file is written whole.

… write, write the files :file: output.zig
[source,zig]

// T4, L9
var written: std.ArrayList([]const u8) = .empty;
for (files, existing) |file, slot| {
    if (slot.text) |text| {
        if (std.mem.eql(u8, text, file.text)) {
            const stat = try dir.statFile(io, file.path, .{});
            if (isExecutable(stat.permissions) != file.executable) {
                try dir.setFilePermissions(io, file.path, withExecutable(stat.permissions, file.executable), .{});
                try written.append(arena, file.path);
            }
            continue;
        }
    }
    try writeAtomic(io, dir, file.path, file.text, file.executable);
    try written.append(arena, file.path);
}
