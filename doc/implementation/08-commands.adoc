== The Commands

:litmus-dir: src

Everything so far was a stage. This chapter puts the stages together into the commands of the spec:

`litmus tangle [-o DIR] [--force] DOCUMENT...`::
Loads the document set, resolves and checks it, tangles, and writes the files and the map.

`litmus check [-o DIR] DOCUMENT...`::
Tangles in memory and compares the result with the files on disk. This is the round-trip check that an agent runs after every change.

`litmus where [-o DIR] FILE:LINE`::
Looks a line up in the map.

`litmus guide`::
Prints the guide for agents.

`litmus init [-o DIR] DOCUMENT...`::
Prepares a project so that agents find the guide.

`litmus untangle [-o DIR] [-f FILE]... [--force] DOCUMENT...`::
Carries changes in the tangled files back into the documents.

`litmus sync [-o DIR] DOCUMENT...`::
Does whichever of tangle and untangle is needed.

`litmus watch [-o DIR] [--interval MS] DOCUMENT...`::
Runs sync now, and again whenever a file changes.

`litmus adopt [-o DIR] [--companion] [--style FILE] [--diff FILE] DOCUMENT PATH...`::
Writes a new document from files that have none, and marks the lines a diff changed.

`litmus style DOCUMENT...`::
Prints the style file that applies to each document.

`litmus blocks [--changed] DOCUMENT...`::
Lists the labeled blocks of the documents, one line each.

`litmus assemble SKELETON TEMPLATE OUTPUT`::
Writes a document from a template of prose and the blocks of a skeleton.

`main.zig` reads the command line and runs the right command. `compare.zig` is the comparison that `check` makes, `marks.zig` reads a diff for adopt, `assemble.zig` makes a document from a template, and `init.zig` is init. The text of the guide is a file of its own, which the program carries inside it.

The options are `-o DIR`, `--force` for tangle and untangle, and `-f FILE` for untangle (U8), `--interval MS` for watch (W3), `--companion`, `--style FILE` and `--diff FILE` for adopt (A8, A9), and `--changed` for blocks (B1). Each command says which of them it takes, in an `Allowed` value. Anything else that starts with a hyphen is an error, and the rest are the positional arguments: documents, or the `FILE:LINE` of `where`. `parseOptions` prints the problem itself and returns null, and the caller exits with 2.

const Options = struct {
    out_dir: []const u8 = ".",
    force: bool = false,
    /// The files named with `-f` (U8).
    files: []const []const u8 = &.{},
    /// How often watch looks at the files, in milliseconds (W3).
    interval_ms: u64 = 200,
    /// For adopt: the document is a companion (L11), and names this style file (L10).
    companion: bool = false,
    style: ?[]const u8 = null,
    /// For adopt: the diff whose changes are marked (A9).
    diff: ?[]const u8 = null,
    /// For blocks: only the blocks that mark changes (B1).
    changed: bool = false,
    positional: []const []const u8 = &.{},
};

/// Which options a command takes besides `-o DIR`.
const Allowed = struct { force: bool = false, files: bool = false, interval: bool = false, adopt: bool = false, changed: bool = false };

/// Reads `-o DIR`, and `--force` and `-f FILE` when allowed. Prints the problem and returns
/// null on a usage error.
fn parseOptions(ctx: Context, args: []const []const u8, allowed: Allowed) !?Options {
    var options: Options = .{};
    var positional: std.ArrayList([]const u8) = .empty;
    var files: std.ArrayList([]const u8) = .empty;
    var i: usize = 0;
    while (i < args.len) : (i += 1) {
        const arg = args[i];
        if (std.mem.eql(u8, arg, "-o")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: -o needs a directory\n");
                return null;
            }
            options.out_dir = args[i];
        } else if (allowed.force and std.mem.eql(u8, arg, "--force")) {
            options.force = true;
        } else if (allowed.changed and std.mem.eql(u8, arg, "--changed")) {
            options.changed = true;
        } else if (allowed.adopt and std.mem.eql(u8, arg, "--companion")) {
            options.companion = true;
        } else if (allowed.adopt and std.mem.eql(u8, arg, "--style")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: --style needs a file\n");
                return null;
            }
            options.style = args[i];
        } else if (allowed.adopt and std.mem.eql(u8, arg, "--diff")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: --diff needs a file\n");
                return null;
            }
            options.diff = args[i];
        } else if (allowed.interval and std.mem.eql(u8, arg, "--interval")) {
            i += 1;
            const milliseconds = if (i < args.len) std.fmt.parseInt(u64, args[i], 10) catch 0 else 0;
            if (milliseconds == 0) {
                try ctx.err.writeAll("litmus: --interval needs a number of milliseconds\n");
                return null;
            }
            options.interval_ms = milliseconds;
        } else if (allowed.files and std.mem.eql(u8, arg, "-f")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: -f needs a file\n");
                return null;
            }
            try files.append(ctx.arena, args[i]);
        } else if (arg.len > 1 and arg[0] == '-') {
            try ctx.err.print("litmus: unknown option {s}\n", .{arg});
            return null;
        } else {
            try positional.append(ctx.arena, arg);
        }
    }
    options.positional = positional.items;
    options.files = files.items;
    return options;
}

`build` is shared by tangle, check and the commands built on them, and its result also says whether the set is a companion of its code (R1): load, resolve, tangle. `buildInto` also gives back the documents that were found, even when there are errors, which watch needs in order to know what to watch (W2). If any stage reports a problem, the diagnostics are sorted, printed, and `null` is returned. When the loading stage has found problems, the checks of the whole set are not run, because they would be answers about a set that was read wrongly: a label that failed to parse would make its excerpt unused, and so on.

A companion's map holds document lines, and a writer who writes prose, or moves blocks, moves them without changing any code. Then nothing needs carrying over, but the map is out of date, and `where` would answer with old lines. `refreshMap` rewrites it when it differs from what the documents give now, and does nothing otherwise. Untangle calls it when it finds nothing to carry over, and so does sync when everything is in sync (R2).

fn refreshMap(ctx: Context, built: Built, map_dir: Io.Dir, old_text: ?[]const u8) !bool {
    const new_map = try map.render(ctx.arena, built.docs, built.files);
    if (old_text) |old| if (std.mem.eql(u8, old, new_map)) return false;
    try output.writeAtomic(ctx.io, map_dir, output.map_path, new_map, false);
    return true;
}

/// The directory that holds the map: `DIR`, or for a companion the directory of the first

fn mapDirPath(options: Options, companion: bool) []const u8 {

fn printDiagnostics(ctx: Context, diags: *types.Diagnostics, docs: []const types.Document) !void {
    diags.sort();
    for (diags.list.items) |d| {
        const path = docs[d.doc].path;
        if (d.line == 0) {
            try ctx.err.print("{s}: {s}\n", .{ path, d.message });
        } else {
            try ctx.err.print("{s}:{d}: {s}\n", .{ path, d.line, d.message });
        }
    }
}

/// Loads, checks and tangles the document set. On errors it prints them and returns null.
fn build(ctx: Context, documents: []const []const u8) !?Built {
    return buildInto(ctx, documents, null);
}

/// Like `build`, and gives the documents that were found even when there are errors, which
/// watch needs to know what to watch.
fn buildInto(ctx: Context, documents: []const []const u8, found: ?*[]const types.Document) !?Built {
    var diags = types.Diagnostics.init(ctx.arena);
    var fs: DiskFs = .{ .io = ctx.io };
    const set = try docset.load(ctx.arena, &fs, documents, &diags);
    if (found) |out| out.* = set.docs;
    // Mistakes in the structure make the checks of the whole set misleading.
    if (diags.list.items.len == 0) {
        const resolved = try resolve.resolve(ctx.arena, set.docs, set.blocks, &diags);
        if (diags.list.items.len == 0) {
            return .{ .docs = set.docs, .files = try tangle.tangleAll(ctx.arena, resolved), .companion = set.companion };
        }
    }
    try printDiagnostics(ctx, &diags, set.docs);
    return null;
}

=== The commands

`tangle` builds the set, makes the output directory, and writes. A companion is refused at once, since it must never write to the code it explains (R3). The report is printed after: each conflict (T6), each file written, and each file that is no longer tangled (T5). Files written are on standard output and problems on standard error. The exit code is 1 when a conflict or a damaged map stopped the tangle.

fn checkCommand(ctx: Context, args: []const []const u8) !u8 {
    const options = (try parseOptions(ctx, args, .{})) orelse return 2;
    if (!try documentsOk(ctx, options.positional)) return 2;
    const built = (try build(ctx, options.positional)) orelse return 1;

    var dir = Io.Dir.cwd().openDir(ctx.io, options.out_dir, .{}) catch |e| {
        try ctx.err.print("{s}: {s}\n", .{ options.out_dir, @errorName(e) });
        return 1;

    defer dir.close(ctx.io);
    const differences = try compare.compare(ctx.io, ctx.arena, dir, built.docs, built.files);
    for (differences) |difference| try difference.print(ctx.err);
    return if (differences.len > 0) 1 else 0;
}

The map is read from where the set keeps it: under the output directory, or beside the first document of a companion (R2).

Untangle's base is the documents tangled in memory (U1). That is right only if the documents' code is what tangle last wrote. If it is not, the documents changed too, and the differences between the files and the base would partly be the documents' own edits, which untangle would take back. So the tangled text of every file is compared with the hash in the map, and any difference stops the command (U1, U7). Without a map nothing can be known, and that stops it too. `--force` skips this, for the writer who knows the documents did not change.

=== Watch

`watch` keeps the documents and the files in step while the writer works (W1 to W5). It does not decide anything about the files itself. It decides _when_, and then asks sync.

++++
<pre class="mermaid">
flowchart TD
  start([litmus watch]) --> run[Run sync once]
  run --> look[Look at every watched file again<br/>so that what sync wrote is not a change]
  look --> sleep[Sleep one interval]
  sleep --> poll[Look at every watched file]
  poll --> moved{Did anything change<br/>since the last look?}
  moved -- no --> quiet{Was there a change before,<br/>and is it quiet for one interval now?}
  moved -- yes --> restart[Start waiting again]
  restart --> sleep
  quiet -- no --> sleep
  quiet -- yes --> run
</pre>
++++

Two things in the picture are rules of the spec. After a run, the files are looked at again before waiting (W4), so Litmus's own writes are never taken for the writer's. And a run that stops, because both sides changed or a document has an error, is not repeated: the loop goes back to sleep, and only a new change wakes it (W5).

The waiting is the part that is easy to get wrong, so here it is run on a small example. A writer saves three times in a row, and once more later. Each dot is a look at the files. Step through it.

The functions that look at files and compare the looks are in `watch.zig`, which is small enough to show whole.

What watch remembers between looks is a `Seen`: the paths it watches, and what it saw of them. A path list and a snapshot are made together in one arena of their own, because both are replaced after every run, and a program that runs for hours must not keep every run's memory. The documents of the set may change from one run to the next (W2), so the paths are copied out of the run's arena before it is freed. `seconds` is the time since the start, for the heading of each run.

/// What watch remembers between looks: the files it watches and what it saw of them. It
/// owns an arena, which is replaced as a whole.
const Seen = struct {
    arena: std.heap.ArenaAllocator,
    paths: []const []const u8,
    snapshot: watch.Snapshot,

    fn take(io: Io, paths: []const []const u8) !Seen {
        var arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
        errdefer arena.deinit();
        const copies = try arena.allocator().alloc([]const u8, paths.len);
        for (paths, copies) |path, *copy| copy.* = try arena.allocator().dupe(u8, path);
        return .{ .arena = arena, .paths = copies, .snapshot = try watch.take(io, arena.allocator(), copies) };
    }

    fn deinit(self: *Seen) void {
        self.arena.deinit();
    }
};

fn seconds(io: Io, since: Io.Timestamp) f64 {
    const ns = since.durationTo(Io.Timestamp.now(io, .awake)).nanoseconds;
    return @as(f64, @floatFromInt(ns)) / 1e9;
}

/// The paths whose existence, size or modification time differ between two snapshots
/// (W3). A path that is in only one of them is a change.
pub fn changed(arena: Allocator, old: Snapshot, new: Snapshot) Allocator.Error![]const []const u8 {
    var result: std.ArrayList([]const u8) = .empty;
    var seen: std.StringHashMapUnmanaged(Entry) = .empty;
    for (old.entries) |entry| try seen.put(arena, entry.path, entry);
    for (new.entries) |entry| {
        const before = seen.get(entry.path) orelse {
            try result.append(arena, entry.path);
            continue;
        };
        _ = seen.remove(entry.path);
        if (before.exists != entry.exists or before.size != entry.size or before.mtime != entry.mtime) {
            try result.append(arena, entry.path);
        }
    }
    for (old.entries) |entry| {
        if (seen.contains(entry.path)) try result.append(arena, entry.path);
    }
    return result.items;

The debounce is a small state machine and takes the time as a number, so it can be tested without waiting. Every look tells it whether anything changed. A change starts the wait, and any further change starts it again. When a look finds nothing changed and the time since the last change has reached the quiet time, `observe` returns true, once. That is the moment for a run (W1).

… Debounce :file: watch.zig

/// W1: a change starts a wait, every further change starts it again, and the files are
/// ready to be acted on when nothing changed for `quiet` nanoseconds.
pub const Debounce = struct {
    quiet: i64,
    last_change: ?i64 = null,

    /// Tells the debounce what one look found, and the time of it. Returns true once, when
    /// the files have been quiet for long enough after a change.
    pub fn observe(self: *Debounce, found_change: bool, now: i64) bool {
        if (found_change) {
            self.last_change = now;
            return false;
        }
        const last = self.last_change orelse return false;
        if (now - last < self.quiet) return false;
        self.last_change = null;
        return true;
    }
};

=== Adopt and style

`adopt` writes a new document from files that have none (A1 to A8). The work of splitting the code is in `adopt.zig`, below; the command finds the files, reads them, and makes sure that what it writes is right.

A path given to adopt is a file or a folder, relative to the output directory. A folder stands for every file in it, found recursively and taken in sorted order, so the same folder always gives the same document. Hidden entries and the usual build folders are passed over (A1).

/// A1: the files of a path under `dir`, a file itself or the files in a folder, in sorted order.
fn collectFiles(ctx: Context, dir: Io.Dir, path: []const u8, out: *std.ArrayList([]const u8)) !void {
    const stat = dir.statFile(ctx.io, path, .{}) catch |e| {
        try ctx.err.print("{s}: {s}\n", .{ path, @errorName(e) });
        return error.NotFound;
    };
    if (stat.kind != .directory) {
        try out.append(ctx.arena, path);
        return;
    }
    var sub = try dir.openDir(ctx.io, path, .{ .iterate = true });
    defer sub.close(ctx.io);
    var names: std.ArrayList([]const u8) = .empty;
    var it = sub.iterate();
    while (try it.next(ctx.io)) |entry| {
        if (entry.name.len == 0 or entry.name[0] == '.') continue;
        const skip = entry.kind == .directory and for (skipped_folders) |s| {
            if (std.mem.eql(u8, s, entry.name)) break true;
        } else false;
        if (!skip) try names.append(ctx.arena, try ctx.arena.dupe(u8, entry.name));
    }
    std.mem.sort([]const u8, names.items, {}, struct {
        fn less(_: void, a: []const u8, b: []const u8) bool {
            return std.mem.order(u8, a, b) == .lt;
        }
    }.less);
    for (names.items) |name| {
        const child = if (std.mem.eql(u8, path, ".")) name else try std.fs.path.join(ctx.arena, &.{ path, name });
        try collectFiles(ctx, dir, child, out);
    }
}

=== Where excerpts start

The splitting rule is one function, used at two levels. An item starts at a line that has the given indent and nothing more, after a blank line, and is not a closing bracket (A4). At the top level the indent is empty. Inside a type it is the indent of the type's body (A5). An item ends at its last non-blank line, so the blank lines between items stay outside them, where the file root, or the type's own block, holds them.

Comments directly above a declaration have no blank line between them and it, so they stay in the same item. That is how a doc comment stays with what it documents.

/// A stretch of lines, `[first, last]`, that becomes one excerpt, or stays in its parent block
/// when it holds only comments.
const Item = struct { first: usize, last: usize };

/// Splits lines into items (A4, A5): an item starts at a line with no indent beyond `indent`,
/// that is not a closing brace, and follows a blank line. The first item starts at the first
/// non-blank line. Each item ends at its last non-blank line.
fn items(arena: Allocator, lines: []const []const u8, from: usize, to: usize, indent: []const u8) ![]const Item {
    var result: std.ArrayList(Item) = .empty;
    var start: ?usize = null;
    var last_text: usize = from;
    var after_blank = true;
    for (from..to) |i| {
        const line = lines[i];
        if (isBlank(line)) {
            after_blank = true;
            continue;
        }
        const starts = after_blank and std.mem.startsWith(u8, line, indent) and line.len > indent.len and
            line[indent.len] != ' ' and line[indent.len] != '\t' and line[indent.len] != '}' and line[indent.len] != ')';
        if (starts or start == null) {
            if (start) |s| try result.append(arena, .{ .first = s, .last = last_text });
            start = i;
        }
        last_text = i;
        after_blank = false;
    }
    if (start) |s| try result.append(arena, .{ .first = s, .last = last_text });
    return result.items;
}

=== Names

An excerpt is named after its declaration (A6). The first line that is not a comment or an attribute is read word by word. Keywords and modifiers are skipped, and so are attributes such as `@MainActor` or `@available(iOS 17, *)`, with their arguments. The first word left is the name. A few cases are special: an operator after `func`, as in `static func ==`, is the name; an extension is named `extension Type`, so it does not clash with the type; and a Zig test is named after its string. A line with no name, such as `comptime {`, gives `block`.

/// The name of an excerpt, from its first line that is not a comment or an attribute (A6).
fn nameOf(arena: Allocator, lines: []const []const u8, item: Item) ![]const u8 {
    for (lines[item.first .. item.last + 1]) |raw| {
        if (isBlank(raw) or isComment(raw)) continue;
        const line = std.mem.trim(u8, raw, " \t\r");
        // A test is named after its string.
        if (std.mem.startsWith(u8, line, "test \"")) {
            const end = std.mem.indexOfScalarPos(u8, line, 6, '"') orelse line.len;
            return try std.fmt.allocPrint(arena, "test {s}", .{line[6..end]});
        }
        var extension = false;
        var after_func = false;
        var i: usize = 0;
        while (i < line.len) {
            while (i < line.len and (line[i] == ' ' or line[i] == '\t')) i += 1;
            if (i >= line.len) break;
            // An attribute such as `@MainActor` or `@available(iOS 17, *)` is skipped whole.
            if (line[i] == '@') {
                i += 1;
                while (i < line.len and isNameChar(line[i])) i += 1;
                if (i < line.len and line[i] == '(') {
                    var depth: usize = 0;
                    while (i < line.len) : (i += 1) {
                        if (line[i] == '(') depth += 1;
                        if (line[i] == ')') {
                            depth -= 1;
                            if (depth == 0) {
                                i += 1;
                                break;
                            }
                        }
                    }
                }
                continue;
            }
            const start = i;
            if (isNameChar(line[i])) {
                while (i < line.len and isNameChar(line[i])) i += 1;
            } else if (after_func) {
                // An operator, such as `==` in `static func ==`.
                while (i < line.len and line[i] != ' ' and line[i] != '(' and line[i] != '\t') i += 1;
            } else break;
            const word = line[start..i];
            after_func = std.mem.eql(u8, word, "func");
            // Words such as `private(set)` carry their parentheses.
            if (i < line.len and line[i] == '(' and isKeyword(word)) {
                while (i < line.len and line[i] != ')') i += 1;
                i += 1;
            }
            if (std.mem.eql(u8, word, "extension")) {
                extension = true;
                continue;
            }
            if (isKeyword(word)) continue;
            if (word.len == 0) {
                i += 1;
                continue;
            }
            return if (extension) try std.fmt.allocPrint(arena, "extension {s}", .{word}) else word;
        }
        // A line of only attributes, such as `@MainActor`, is followed by the declaration.
        if (line.len > 0 and line[0] == '@') continue;
        break;
    }
    return "block";
}

The language of each block, for the highlighting on the page, comes from the file's extension. Every block gets a source line, and a file whose extension is not in the table gets `[source,text]` (A7). The names are the ones Asciidoctor and GitHub use. Rouge, which renders the book, has no lexer for some of them, such as `antlr` for ANTLR grammars; it shows those blocks as plain text, and GitHub still highlights them. A bare `[source]` would not do: Asciidoctor would then highlight the block in the document's default language, and with no line at all, a block title added later would be read as part of the label above it. The block's delimiter is a line of hyphens one longer than the longest line of only hyphens in the code, so that no line of code can close the block early (A7).

    const ext = std.fs.path.extension(path);
    const table = [_][2][]const u8{
        .{ ".zig", "zig" },  .{ ".swift", "swift" }, .{ ".c", "c" },         .{ ".h", "c" },
        .{ ".m", "objc" },   .{ ".cpp", "cpp" },     .{ ".hpp", "cpp" },     .{ ".rs", "rust" },
        .{ ".go", "go" },    .{ ".py", "python" },   .{ ".js", "javascript" }, .{ ".ts", "typescript" },
        .{ ".sh", "bash" },  .{ ".rb", "ruby" },     .{ ".java", "java" },   .{ ".kt", "kotlin" },
        .{ ".json", "json" }, .{ ".yml", "yaml" },   .{ ".yaml", "yaml" },   .{ ".toml", "toml" },
        .{ ".cc", "cpp" },   .{ ".mm", "objc" },     .{ ".cs", "csharp" },   .{ ".lua", "lua" },
        .{ ".sql", "sql" },  .{ ".html", "html" },   .{ ".css", "css" },     .{ ".xml", "xml" },

/// A7: a line of hyphens one longer than the longest line of only hyphens in the code.
fn delimiter(arena: Allocator, lines: []const []const u8) ![]const u8 {
    var longest: usize = 3;
    for (lines) |line| {
        const body = std.mem.trimEnd(u8, line, "\r");
        if (body.len == 0) continue;
        for (body) |c| {
            if (c != '-') break;
        } else longest = @max(longest, body.len);
    }
    const result = try arena.alloc(u8, longest + 1);
    @memset(result, '-');
    return result;
}

=== Writing the document

A `Writer` collects the document's text and counts the excerpts. `block` writes one labeled block. A file's root block is written first, and then its _parts_, in the order of the file: the headings that `MARK` lines give, and the excerpts.

Before any of that, `problemOf` says whether a file can go into a document at all (A2): a line that starts with an ellipsis would be read as an excerpt command (L4), a line that starts with `include::` is not allowed in a labeled block (L6), and a file with no final newline cannot be tangled back, since tangled files always end with one (T3).

/// The output being built, with the blocks of one file that are still to be written.
const Writer = struct {
    arena: Allocator,
    out: std.ArrayList(u8) = .empty,
    excerpts: u32 = 0,

    fn print(self: *Writer, comptime fmt: []const u8, args: anytype) !void {
        try self.out.print(self.arena, fmt, args);
    }

    /// Writes a labeled block (A7).
    fn block(self: *Writer, name: ?[]const u8, path: []const u8, language: []const u8, lines: []const []const u8) !void {
        if (name) |n| {
            try self.print("{s} {s} :file: {s}\n", .{ ellipsis, n, path });
            self.excerpts += 1;
        } else {
            try self.print("{s} :file: {s}\n", .{ ellipsis, path });
        }
        try self.print("[source,{s}]\n", .{language});
        const delim = try delimiter(self.arena, lines);
        try self.print("{s}\n", .{delim});
        for (lines) |line| try self.print("{s}\n", .{line});
        try self.print("{s}\n\n", .{delim});
    }
};

/// A block to write after the file root, in order: a heading or an excerpt.
const Part = union(enum) {
    heading: []const u8,
    excerpt: struct { name: []const u8, lines: []const []const u8 },
};

/// A2: why a file cannot go into a document, or null.
fn problemOf(text: []const u8, lines: []const []const u8) ?struct { line: u32, reason: []const u8 } {
    if (text.len > 0 and text[text.len - 1] != '\n') {
        return .{ .line = @intCast(lines.len), .reason = "A2: the file does not end with a newline, and a tangled file always does (T3)" };
    }
    for (lines, 1..) |line, n| {
        const body = std.mem.trimStart(u8, line, " \t");
        if (std.mem.startsWith(u8, body, ellipsis ++ " ")) return .{ .line = @intCast(n), .reason = "A2: the line starts with an ellipsis, and would be read as an excerpt command (L4)" };
        if (std.mem.startsWith(u8, line, "include::")) return .{ .line = @intCast(n), .reason = "A2: the line starts with include::, which is not allowed in a labeled block (L6)" };
    }
    return null;
}

/// Adopts one file: its root block, and the parts that follow it.
fn adoptFile(w: *Writer, source: Source) !void {
    const arena = w.arena;
    const lines = try @import("scan.zig").splitLines(arena, source.text);
    const language = languageOf(source.path);
    var taken: std.StringHashMapUnmanaged(void) = .empty;
    var root: std.ArrayList([]const u8) = .empty;
    var parts: std.ArrayList(Part) = .empty;

    const top = try items(arena, lines, 0, lines.len, "");
    var at: usize = 0;
    for (top) |item| {
        // The blank lines between items stay in the root.
        while (at < item.first) : (at += 1) try root.append(arena, lines[at]);
        at = item.last + 1;
        const body = lines[item.first .. item.last + 1];

        // An item of only comments stays in the root, and a MARK line is a heading (A3).
        var only_comments = true;
        for (body) |line| if (!isBlank(line) and !isComment(line)) {
            only_comments = false;
        };
        if (only_comments) {
            for (body) |line| {
                try root.append(arena, line);
                if (markTitle(line)) |title| try parts.append(arena, .{ .heading = title });
            }
            continue;
        }
        if (markTitle(body[0])) |title| try parts.append(arena, .{ .heading = title });

        const name = try unique(arena, &taken, try nameOf(arena, lines, item));
        try root.append(arena, try std.fmt.allocPrint(arena, "{s} {s}", .{ ellipsis, name }));
        try splitItem(arena, &parts, &taken, lines, item, name);
    }
    while (at < lines.len) : (at += 1) try root.append(arena, lines[at]);

    try w.print("== {s}\n\n", .{source.path});
    try w.block(null, source.path, language, root.items);
    for (parts.items) |part| switch (part) {
        .heading => |title| try w.print("=== {s}\n\n", .{title}),
        .excerpt => |e| try w.block(e.name, source.path, language, e.lines),
    };
}

=== Splitting a type

`splitItem` decides whether an item is split one level deeper (A5). It must be long, its declaration line must end with `{`, and its last line must be `}` or `};`. Every line of the body must also have the body's indent, or be blank. If any line has less, as a Swift `#if` at column 0 does, the item stays whole: taking the indent off that line would change it, and the round trip would fail.

When it is split, the type's own block keeps its declaration line, the lines between members, and its closing line, and gets an excerpt command at the body's indent for each member. Each member's lines lose that indent, since the command puts it back (T2). Members are named `Type.member`.

/// A5: a long item in braces is split one level deeper. Otherwise it is one excerpt.
fn splitItem(arena: Allocator, parts: *std.ArrayList(Part), taken: *std.StringHashMapUnmanaged(void), lines: []const []const u8, item: Item, name: []const u8) !void {
    const whole = lines[item.first .. item.last + 1];
    // The declaration's first line, past the comments and attributes above it.
    var open = item.first;
    while (open < item.last and (isComment(lines[open]) or std.mem.startsWith(u8, std.mem.trim(u8, lines[open], " \t\r"), "@"))) open += 1;
    const opens = std.mem.endsWith(u8, std.mem.trimEnd(u8, lines[open], " \t\r"), "{");
    const close = std.mem.trimEnd(u8, lines[item.last], " \t\r");
    const closes = std.mem.eql(u8, close, "}") or std.mem.eql(u8, close, "};");
    if (whole.len <= split_above or !opens or !closes or open + 1 >= item.last) {
        try parts.append(arena, .{ .excerpt = .{ .name = name, .lines = whole } });
        return;
    }
    var first_text = open + 1;
    while (first_text < item.last and isBlank(lines[first_text])) first_text += 1;
    const indent = indentOf(lines[first_text]);
    // Every line of the body must have the indent, or be blank, or the split is not safe.
    for (lines[open + 1 .. item.last]) |line| {
        if (!isBlank(line) and !std.mem.startsWith(u8, line, indent)) {
            try parts.append(arena, .{ .excerpt = .{ .name = name, .lines = whole } });
            return;
        }
    }
    if (indent.len == 0) {
        try parts.append(arena, .{ .excerpt = .{ .name = name, .lines = whole } });
        return;
    }

    const type_name = if (std.mem.startsWith(u8, name, "extension ")) name["extension ".len..] else name;
    const members = try items(arena, lines, open + 1, item.last, indent);
    var parent: std.ArrayList([]const u8) = .empty;
    var children: std.ArrayList(Part) = .empty;
    for (lines[item.first .. open + 1]) |line| try parent.append(arena, line);
    var at = open + 1;
    for (members) |member| {
        while (at < member.first) : (at += 1) try parent.append(arena, lines[at]);
        at = member.last + 1;
        const body = lines[member.first .. member.last + 1];
        var only_comments = true;
        for (body) |line| if (!isBlank(line) and !isComment(line)) {
            only_comments = false;
        };
        if (only_comments) {
            for (body) |line| {
                try parent.append(arena, line);
                if (markTitle(line)) |title| try children.append(arena, .{ .heading = title });
            }
            continue;
        }
        if (markTitle(body[0])) |title| try children.append(arena, .{ .heading = title });
        const member_name = try unique(arena, taken, try std.fmt.allocPrint(arena, "{s}.{s}", .{ type_name, try nameOf(arena, lines, member) }));
        try parent.append(arena, try std.fmt.allocPrint(arena, "{s}{s} {s}", .{ indent, ellipsis, member_name }));
        const dedented = try arena.alloc([]const u8, body.len);
        for (body, dedented) |line, *d| d.* = if (isBlank(line) and line.len < indent.len) line else line[indent.len..];
        try children.append(arena, .{ .excerpt = .{ .name = member_name, .lines = dedented } });
    }
    while (at <= item.last) : (at += 1) try parent.append(arena, lines[at]);
    try parts.append(arena, .{ .excerpt = .{ .name = name, .lines = parent.items } });
    try parts.appendSlice(arena, children.items);
}

/// The document for the given files (A3 to A8). Files that cannot be adopted are refused,
/// and then there is no document.
pub fn adopt(arena: Allocator, sources: []const Source, options: Options) !Result {
    var refusals: std.ArrayList(Refusal) = .empty;
    for (sources) |source| {
        const lines = try @import("scan.zig").splitLines(arena, source.text);
        if (problemOf(source.text, lines)) |p| try refusals.append(arena, .{ .path = source.path, .line = p.line, .reason = p.reason });
    }
    if (refusals.items.len > 0) return .{ .text = "", .refusals = refusals.items, .excerpts = 0 };

    var w: Writer = .{ .arena = arena };
    try w.print("= {s}\n", .{options.title});
    if (options.style) |style| try w.print(":litmus-style: {s}\n", .{style});
    if (options.companion) try w.print(":litmus-companion:\n", .{});
    try w.print(":toc: left\n:toclevels: 3\n:sectanchors:\n\n", .{});
    try w.print("This document was made by `litmus adopt` from {d} {s}. Each file is a section, with its code split into excerpts at its declarations. The excerpts can be moved into the order that explains the code best, and the prose goes between them.\n\n", .{ sources.len, if (sources.len == 1) "file" else "files" });
    for (sources) |source| try adoptFile(&w, source);
    return .{ .text = w.out.items, .refusals = &.{}, .excerpts = w.excerpts };
}

The `---` and `+++` lines name the file. Git adds a tab after a name that has a space in it, puts quotes around a name with unusual bytes, and writes escapes inside them, with bytes beyond ASCII in octal. All of that is undone, and the `a/` or `b/` that git puts in front is taken off, so the path is relative to the repository's root, as adopt's paths are.

… diff paths :file: marks.zig
[source,zig]
----
/// A path of a `---` or `+++` line: without the tab and what follows it, without the
/// quotes git puts around unusual names, and without a leading `a/` or `b/`.
fn diffPath(arena: Allocator, raw: []const u8) ![]const u8 {
    var path = raw;
    if (std.mem.indexOfScalar(u8, path, '\t')) |tab| path = path[0..tab];
    path = std.mem.trimEnd(u8, path, " \r");
    if (path.len >= 2 and path[0] == '"' and path[path.len - 1] == '"') {
        // C-style escapes: \\, \", \t, \n, and octal bytes such as \303.
        var out: std.ArrayList(u8) = .empty;
        var i: usize = 1;
        while (i < path.len - 1) : (i += 1) {
            const c = path[i];
            if (c != '\\' or i + 1 >= path.len - 1) {
                try out.append(arena, c);
                continue;
            }
            i += 1;
            switch (path[i]) {
                't' => try out.append(arena, '\t'),
                'n' => try out.append(arena, '\n'),
                '0'...'7' => {
                    var value: u32 = 0;
                    var digits: usize = 0;
                    while (digits < 3 and i < path.len - 1 and path[i] >= '0' and path[i] <= '7') : (digits += 1) {
                        value = value * 8 + (path[i] - '0');
                        i += 1;
                    }
                    i -= 1;
                    try out.append(arena, @truncate(value));
                },
                else => |e| try out.append(arena, e),
            }
        }
        path = out.items;
    }
    if (std.mem.startsWith(u8, path, "a/") or std.mem.startsWith(u8, path, "b/")) path = path[2..];
    return path;
}

A hunk header gives each side as a start and a count. The count may be left out when it is 1.

… hunk ranges :file: marks.zig
[source,zig]
----
/// The start and count of one side of a hunk header, such as `12,3` or `12`.
fn range(text: []const u8) ?struct { start: u32, count: u32 } {
    const comma = std.mem.indexOfScalar(u8, text, ',');
    const start = std.fmt.parseInt(u32, if (comma) |c| text[0..c] else text, 10) catch return null;
    const count = if (comma) |c| std.fmt.parseInt(u32, text[c + 1 ..], 10) catch return null else 1;
    return .{ .start = start, .count = count };
}
----

Each hunk is read by its counts, not by the first character of its lines alone: a removed line whose text starts with `--` looks like a `---` line, and only the counts say it is part of the hunk. `at` is the number of new-side lines before the next line of the hunk. For a hunk that adds nothing, git gives the line after which the removal happened, not the first line, so `at` starts there.

Removed and added lines that are next to each other form a group. A group of one removed line and one added line is a line that was replaced: it is changed, and not also removed. Only the removed lines beyond the added ones count as removed, after the group's last line. A diff that ends inside a hunk, or a hunk longer than its header, is reported with its line, and nothing comes back.

[source,zig]
----
/// A9: the changes of each file a unified diff names. A file the diff deletes is left out.
pub fn parse(arena: Allocator, text: []const u8) !Parsed {
    const lines = try @import("scan.zig").splitLines(arena, text);
    var files: std.ArrayList(FileChange) = .empty;
    var added: std.ArrayList(u32) = .empty;
    var removed: std.ArrayList(Removal) = .empty;
    var path: ?[]const u8 = null;

    var i: usize = 0;
    while (i < lines.len) : (i += 1) {
        const line = lines[i];
        if (std.mem.startsWith(u8, line, "+++ ")) {
            if (path) |p| try files.append(arena, .{ .path = p, .added = try added.toOwnedSlice(arena), .removed = try removed.toOwnedSlice(arena) });
            const name = try diffPath(arena, line[4..]);
            path = if (std.mem.eql(u8, name, "/dev/null")) null else name;
            continue;
        }
        if (!std.mem.startsWith(u8, line, "@@ -")) continue;

        // @@ -a,b +c,d @@
        const bad: Parsed = .{ .files = &.{}, .problem = .{ .line = @intCast(i + 1), .reason = "A9: a hunk header that cannot be read" } };
        const rest = line[4..];
        const space = std.mem.indexOfScalar(u8, rest, ' ') orelse return bad;
        const old = range(rest[0..space]) orelse return bad;
        if (!std.mem.startsWith(u8, rest[space..], " +")) return bad;
        const after_plus = rest[space + 2 ..];
        const end = std.mem.indexOfScalar(u8, after_plus, ' ') orelse return bad;
        const new = range(after_plus[0..end]) orelse return bad;

        // The new side's lines before the next line of the hunk.
        var at: u32 = if (new.count == 0) new.start else new.start - @min(new.start, 1);
        var old_left = old.count;
        var new_left = new.count;
        // The group of removed and added lines being read.
        var minus: u32 = 0;
        var plus: u32 = 0;
        while (old_left > 0 or new_left > 0) {
            i += 1;
            if (i >= lines.len) return .{ .files = &.{}, .problem = .{ .line = @intCast(lines.len), .reason = "A9: the diff ends inside a hunk" } };
            const body = lines[i];
            const too_long: Parsed = .{ .files = &.{}, .problem = .{ .line = @intCast(i + 1), .reason = "A9: the hunk has more lines than its header says" } };
            // Some tools drop the space of an empty line of context.
            switch (if (body.len == 0) ' ' else body[0]) {
                '\\' => continue, // "\ No newline at end of file"
                ' ' => {
                    if (path != null and minus > plus) try removed.append(arena, .{ .after = at, .count = minus - plus });
                    minus = 0;
                    plus = 0;
                    if (old_left == 0 or new_left == 0) return too_long;
                    old_left -= 1;
                    new_left -= 1;
                    at += 1;
                },
                '+' => {
                    if (new_left == 0) return too_long;
                    new_left -= 1;
                    at += 1;
                    plus += 1;
                    if (path != null) try added.append(arena, at);
                },
                '-' => {
                    if (old_left == 0) return too_long;
                    old_left -= 1;
                    minus += 1;
                },
                else => return .{ .files = &.{}, .problem = .{ .line = @intCast(i + 1), .reason = "A9: a line of a hunk that is neither context, added nor removed" } },
            }
        }
        if (path != null and minus > plus) try removed.append(arena, .{ .after = at, .count = minus - plus });
    }
    if (path) |p| try files.append(arena, .{ .path = p, .added = try added.toOwnedSlice(arena), .removed = try removed.toOwnedSlice(arena) });
    return .{ .files = files.items };
}

pub fn ranges(arena: Allocator, numbers: []const u32) ![]const u8 {
    var out: std.ArrayList(u8) = .empty;
    var i: usize = 0;
    while (i < numbers.len) {
        var j = i;
        while (j + 1 < numbers.len and numbers[j + 1] == numbers[j] + 1) j += 1;

fn origin(file: tangle.Tangled, line: u32) ?struct { block: *const Block, index: u32 } {
    const r = map.findRun(file.runs, line) orelse return null;

Marking is a walk over the changes. Each added line is traced to its block. A removal is traced to the line it follows, or to the file's first line when it is at the start, and the last line when the file is shorter. Then each marked block's source line gets the attributes, before its closing bracket. Adopt writes the source line two lines above the code, which is how it is found; a line that does not look like one is left alone.

… mark :file: marks.zig
[source,zig]
----
/// A9: the lines of an adopted document, with the marks of L12 on the source lines of the
/// blocks that hold changed lines. `files` are the document's files, tangled. Adopt
/// writes each source line two lines above the block's first line of code.
pub fn mark(arena: Allocator, doc_lines: []const []const u8, files: []const tangle.Tangled, changes: []const FileChange) !Marked {
    var marks: std.AutoArrayHashMapUnmanaged(*const Block, Marks) = .empty;
    for (changes) |change| {
        const file = for (files) |f| {
            if (std.mem.eql(u8, f.path, change.path)) break f;
        } else continue;
        const count: u32 = @intCast(std.mem.countScalar(u8, file.text, '\n'));
        for (change.added) |line| {
            const o = origin(file, line) orelse continue;
            const entry = try marks.getOrPutValue(arena, o.block, .{});
            try entry.value_ptr.lines.append(arena, o.index);
        }
        for (change.removed) |removal| {
            if (count == 0) continue;
            const o = origin(file, @min(@max(removal.after, 1), count)) orelse continue;
            const entry = try marks.getOrPutValue(arena, o.block, .{});
            entry.value_ptr.removed += removal.count;
        }
    }

    const result = try arena.dupe([]const u8, doc_lines);
    var marked: u32 = 0;
    var it = marks.iterator();
    while (it.next()) |entry| {
        const block = entry.key_ptr.*;
        const m = entry.value_ptr;
        const at = block.first_line - 3;
        const source = result[at];
        if (!std.mem.startsWith(u8, source, "[source,") or !std.mem.endsWith(u8, source, "]")) continue;
        var line: std.ArrayList(u8) = .empty;
        try line.appendSlice(arena, source[0 .. source.len - 1]);
        if (m.lines.items.len > 0) {
            std.mem.sort(u32, m.lines.items, {}, lessU32);
            try line.print(arena, ",litmus-changed=\"{s}\"", .{try ranges(arena, m.lines.items)});
        }
        if (m.removed > 0) try line.print(arena, ",litmus-removed=\"{d}\"", .{m.removed});
        try line.append(arena, ']');
        result[at] = line.items;
        marked += 1;
    }
    return .{ .lines = result, .blocks = marked };
}

/// L12: the value of `name="..."` in a block attribute line, or null.
pub fn attribute(line: []const u8, name: []const u8) ?[]const u8 {
    var from: usize = 0;
    while (std.mem.indexOfPos(u8, line, from, name)) |at| {
        from = at + name.len;
        const before_ok = at > 0 and (line[at - 1] == ',' or line[at - 1] == '[');

        const start = from + 2;
        const end = std.mem.indexOfScalarPos(u8, line, start, '"') orelse return null;
        return line[start..end];
    }
    return null;
}

/// A9: the text of an adopted document with the marks of the changes. The document must
/// pass the checks, as adopt's does by construction.
pub fn markDocument(arena: Allocator, doc: types.Document, changes: []const FileChange) !struct { text: []const u8, blocks: u32 } {
    var diags = types.Diagnostics.init(arena);
    const parsed = try @import("parse.zig").parse(arena, 0, doc, &diags);
    const resolved = try @import("resolve.zig").resolve(arena, try arena.dupe(types.Document, &.{doc}), parsed.blocks, &diags);

        try out.append(arena, '\n');

=== Assembling a document

Writing a document by moving the blocks of a skeleton is slow, and easy to get wrong: a block lost, or copied with a line changed. `assemble` lets the writer write only prose, with a line where each block goes, and copies the blocks from the skeleton exactly (S1 to S4). It is the cheap way for an agent to write a document: it writes the prose and the placeholders, and never writes code out again.

The command takes three documents. It refuses to write over the skeleton or the template, which it compares as paths, and the skeleton must load, resolve and tangle like any document set, since its files are what the output must give back.

    const template_text = cwd.readFileAlloc(ctx.io, template, ctx.arena, .limited(1 << 30)) catch |e| {

        try ctx.err.print("{s}:{d}: {s}\n", .{ if (p.in_skeleton) set.docs[0].path else template, p.line, p.message });

        return 1;

        .format = .asciidoc,
        .lines = try @import("scan.zig").splitLines(ctx.arena, result.text),
        .dir = std.fs.path.dirname(output_path) orelse "",

fn placeholder(text: []const u8) ?struct { name: ?[]const u8, path: []const u8 } {
    var rest: []const u8 = undefined;
    var name: ?[]const u8 = null;
    if (std.mem.startsWith(u8, text, ":file: ")) {

Each line of the template is classified by the scanner, so that commands inside listings, comments and passthrough blocks are left alone (L5). A document command is a placeholder unless a block follows it after any attribute and title lines. To look ahead without losing its place, a copy of the scanner reads the lines that follow. A placeholder's path is matched exactly first, and otherwise by its end after a `/`, which must fit one file only: skeletons have long paths, and a writer should not need to spell them out.

[source,zig]
----
// S1: the template, line by line, with each placeholder replaced. `rest_at` is where the
// rest goes, as an index into `out`.
var out: std.ArrayList([]const u8) = .empty;
var rest_at: ?usize = null;
var placed: u32 = 0;
var scanner = scan.Scanner.init(.asciidoc);
for (template, 1..) |line, n| {
    const line_no: u32 = @intCast(n);
    if (scanner.next(line) != .command) {
        try out.append(arena, line);
        continue;
    }
    const text = std.mem.trim(u8, scan.commandOf(line).?.text, " \t\r");
    if (std.mem.eql(u8, text, ":rest:")) {
        if (rest_at != null) {
            try problems.append(arena, .{ .line = line_no, .message = "S3: a second … :rest:" });
        } else rest_at = out.items.len;
        continue;
    }
    // A label that a block follows is the template's own, and stays as it is.
    var look = scanner;
    var follows: scan.Kind = .prose;
    for (template[n..]) |next_line| {
        follows = look.next(next_line);
        if (follows != .attribute and follows != .title) break;
    }
    if (follows == .open) {
        try out.append(arena, line);
        continue;
    }

    const p = placeholder(text) orelse {
        try problems.append(arena, .{ .line = line_no, .message = try std.fmt.allocPrint(arena, "S3: a placeholder needs :file:, as in … NAME :file: PATH: {s}", .{text}) });
        continue;
    };
    // The path, or the end of exactly one file's path.
    var file: ?[]const u8 = null;
    var matches: u32 = 0;
    for (files.items) |f| {
        if (std.mem.eql(u8, f, p.path)) {
            file = f;
            matches = 1;
            break;
        }
        if (f.len > p.path.len and std.mem.endsWith(u8, f, p.path) and f[f.len - p.path.len - 1] == '/') {
            file = f;
            matches += 1;
        }
    }
    if (matches == 0) {
        try problems.append(arena, .{ .line = line_no, .message = try std.fmt.allocPrint(arena, "S3: no file of the skeleton is or ends with {s}", .{p.path}) });
        continue;
    }
    if (matches > 1) {
        try problems.append(arena, .{ .line = line_no, .message = try std.fmt.allocPrint(arena, "S3: more than one file of the skeleton ends with {s}; write more of its path", .{p.path}) });
        continue;
    }
    const entry = for (entries.items) |*e| {
        if (std.mem.eql(u8, e.file, file.?) and sameName(e.name, p.name)) break e;
    } else {
        try problems.append(arena, .{ .line = line_no, .message = try std.fmt.allocPrint(arena, "S3: the skeleton has no block {s} of {s}", .{ p.name orelse "(file root)", file.? }) });
        continue;
    };
    if (entry.used) {
        try problems.append(arena, .{ .line = line_no, .message = try std.fmt.allocPrint(arena, "S3: the block {s} of {s} is placed twice", .{ p.name orelse "(file root)", file.? }) });
        continue;
    }
    entry.used = true;
    for (entry.blocks.items, 0..) |block, i| {
        if (i > 0) try out.append(arena, "");
        try out.appendSlice(arena, span(docs, block));
    }
    placed += @intCast(entry.blocks.items.len);
}

pub const Difference = struct {
    path: []const u8,
    kind: enum { missing, differs, should_be_executable, should_not_be_executable },
    /// For `differs`: the first line that differs, counting from 1.
    line: u32 = 0,
    /// The tangled line and the line on disk, if each exists.
    expected: ?[]const u8 = null,
    found: ?[]const u8 = null,
    /// Where the tangled line, or for a difference past the end the file's last
    /// line, came from.
    origin: ?Origin = null,

    pub const Origin = struct { doc: []const u8, line: u32, excerpt: []const u8 };

    pub fn print(self: Difference, w: *Io.Writer) !void {
        switch (self.kind) {
            .missing => try w.print("{s}: missing\n", .{self.path}),
            .should_be_executable => try w.print("{s}: should be executable\n", .{self.path}),
            .should_not_be_executable => try w.print("{s}: should not be executable\n", .{self.path}),
            .differs => {
                try w.print("{s}:{d}: differs from the tangled text", .{ self.path, self.line });
                if (self.origin) |o| {
                    try w.print("; the line comes from {s}:{d} ({s})", .{ o.doc, o.line, o.excerpt });
                }
                try w.writeAll("\n");
                try w.print("  tangled: {s}\n", .{self.expected orelse "(end of file)"});
                try w.print("  on disk: {s}\n", .{self.found orelse "(end of file)"});
            },
        }
    }
};

/// The line `n` of a text, counting from 1, without its `\n`; null past the end.
fn lineOf(text: []const u8, n: u32) ?[]const u8 {
    var start: usize = 0;
    var i: u32 = 1;
    while (i < n) : (i += 1) {
        start = (std.mem.indexOfScalarPos(u8, text, start, '\n') orelse return null) + 1;
    }
    if (start >= text.len) return null;
    const end = std.mem.indexOfScalarPos(u8, text, start, '\n') orelse text.len;
    return text[start..end];
}

The first difference is found by comparing bytes, and the line is the number of newlines before that byte, plus one. Its origin comes from the runs, by the same search as `where`.

fn compareFile(docs: []const types.Document, file: tangle.Tangled, text: []const u8) !Difference {
    const common = std.mem.indexOfDiff(u8, file.text, text) orelse unreachable;
    const line: u32 = @intCast(std.mem.countScalar(u8, file.text[0..common], '\n') + 1);
    var difference: Difference = .{
        .path = file.path,
        .kind = .differs,
        .line = line,
        .expected = lineOf(file.text, line),
        .found = lineOf(text, line),
    };
    // A difference past the end of the tangled text is reported at its last run.
    if (map.findRun(file.runs, line)) |at| {
        const run = file.runs[at];
        difference.origin = .{ .doc = docs[run.doc].path, .line = run.doc_line + (line - run.line), .excerpt = run.excerpt };
    } else if (file.runs.len > 0) {
        const run = file.runs[file.runs.len - 1];
        difference.origin = .{ .doc = docs[run.doc].path, .line = run.doc_line + run.count - 1, .excerpt = run.excerpt };
    }
    return difference;
}

/// Compares each tangled file with the file of the same path under `dir`.
pub fn compare(io: Io, arena: Allocator, dir: Io.Dir, docs: []const types.Document, files: []const tangle.Tangled) ![]const Difference {
    var result: std.ArrayList(Difference) = .empty;
    for (files) |file| {
        const text = try output.readOrNull(io, arena, dir, file.path) orelse {
            try result.append(arena, .{ .path = file.path, .kind = .missing });
            continue;
        };
        if (!std.mem.eql(u8, text, file.text)) {
            try result.append(arena, try compareFile(docs, file, text));
        }
        if (comptime Io.File.Permissions.has_executable_bit) {
            const stat = try dir.statFile(io, file.path, .{});
            if (output.isExecutable(stat.permissions) != file.executable) {
                try result.append(arena, .{
                    .path = file.path,
                    .kind = if (file.executable) .should_be_executable else .should_not_be_executable,
                });
            }
        }
    }
    return result.items;
}

/// The text with a final `\n`, and `addition` after it.
fn appended(arena: Allocator, existing: []const u8, addition: []const u8) ![]const u8 {
    const newline: []const u8 = if (existing.len > 0 and existing[existing.len - 1] != '\n') "\n" else "";
    return std.mem.concat(arena, u8, &.{ existing, newline, addition });
}

/// Finds a line of `text` that equals `marker` once trimmed: the offset of its start and of its end, past the `\n`.
fn findLine(text: []const u8, marker: []const u8, from: usize) ?struct { start: usize, end: usize } {
    var start = from;
    while (start < text.len) {
        const newline = std.mem.indexOfScalarPos(u8, text, start, '\n');
        const end = if (newline) |n| n + 1 else text.len;
        const line = std.mem.trim(u8, text[start..end], " \t\r\n");
        if (std.mem.eql(u8, line, marker)) return .{ .start = start, .end = end };
        start = end;
    }
    return null;
}

pub fn applyAgents(arena: Allocator, existing: ?[]const u8, para: []const u8) AgentsError!?[]const u8 {
    const text = existing orelse return para;
    var result: []const u8 = undefined;
    if (findLine(text, start_marker, 0)) |start| {
        const end = findLine(text, end_marker, start.end) orelse return error.UnclosedParagraph;
        result = try std.mem.concat(arena, u8, &.{ text[0..start.start], para, text[end.end..] });

        result = try appended(arena, text, if (text.len > 0) try std.mem.concat(arena, u8, &.{ "\n", para }) else para);
    }
    return if (std.mem.eql(u8, result, text)) null else result;

/// Runs init in the current directory, printing each change to `out`. Returns the exit code.
pub fn run(io: Io, arena: Allocator, args: Args, out: *Io.Writer, err: *Io.Writer) !u8 {
    const cwd = Io.Dir.cwd();
    const entry = try ignoreEntry(arena, args.dir);
    const para = try paragraph(arena, args);
    var failed = false;

    const names = [_][]const u8{ "AGENTS.md", "CLAUDE.md", ".gitignore" };
    for (names) |name| {
        const existing = try output.readOrNull(io, arena, cwd, name);
        const updated: ?[]const u8 = if (std.mem.eql(u8, name, "AGENTS.md"))
            applyAgents(arena, existing, para) catch |e| switch (e) {
                error.UnclosedParagraph => {
                    try err.print("{s}: has \"{s}\" but no \"{s}\" after it\n", .{ name, start_marker, end_marker });
                    failed = true;
                    continue;
                },
                else => return e,
            }
        else if (std.mem.eql(u8, name, "CLAUDE.md"))
            try applyClaude(arena, existing)
        else
            try applyGitignore(arena, existing, entry);
        const text = updated orelse continue;
        try output.writeAtomic(io, cwd, name, text, false);
        try out.print("{s} {s}\n", .{ if (existing == null) "created" else "updated", name });
    }
    // I5: the skill is Litmus's own, so an older one is replaced.
    const existing_skill = try output.readOrNull(io, arena, cwd, skill_path);
    if (existing_skill == null or !std.mem.eql(u8, existing_skill.?, skill_text)) {
        try output.writeAtomic(io, cwd, skill_path, skill_text, false);
        try out.print("{s} {s}\n", .{ if (existing_skill == null) "created" else "updated", skill_path });
    }
    return if (failed) 1 else 0;
}

=== The guide

The guide is what `litmus guide` prints. Agents read it before they change a tangled file. It tells them how to find their way (`.litmus/map`, `litmus where`), how to change code so that the documents and the files stay equal, and what never to do. Changing code now goes through untangle: the agent edits and tests the tangled file, runs untangle, writes the prose it asks for, and checks. If watch is running, it does the untangling on every save, and the agent only has to read its output. The guide also says what to do when untangle cannot place a line, or finds that the documents changed too. It is written for an agent, in plain words and short sentences.

It also tells agents to read the style of a document before writing its prose, that every `next:` line says what to do, and where the steps for documents of existing code are.

The spec includes this file, so the text exists once.

Litmus: a guide for agents

Some files in this project are tangled. Their code lives in documents, asciidoc or
Markdown, that explain it. A tangled file must always equal what its documents
tangle to. AGENTS.md gives this project's commands for tangle and check.

Finding your way
- .litmus/map lists every tangled file: each line starting with "file" names one.
- `litmus where FILE:LINE` prints the document line, and the excerpt, that a line
  of a tangled file came from. It works for lines in compiler errors too.
- A document labels each block of code with the file it lands in:
  `… name :file: path` for an excerpt, `… :file: path` for the start of a file.
  Inside a block, a line `… name` inserts that excerpt, at that indent.

Changing code
1. Edit the tangled file and test it as usual.
2. Run the untangle command from AGENTS.md. It carries the change into the
   document's blocks, and lists the blocks that need prose.
3. Write the prose for every block it lists: what the new code does and why.
   If new code deserves a block of its own, put it in one, labeled with its name
   and file and inserted by exactly one `… name` line.
4. Run the check command from AGENTS.md. The change is done only when it passes.

Before you write prose for a document, run `litmus style DOCUMENT` and follow
the style file it names. Every `next:` line that Litmus prints says what to do.

If `litmus watch` is running in this project, it does step 2 by itself whenever a
file is saved. Read its output: it still lists the blocks that need prose.

Never
- edit .litmus/map;
- run `litmus tangle --force` or `litmus untangle --force` unless the user asks:
  they skip the protection of edits;
- start a line of code with `…` (U+2026);
- leave a tangled file changed without the same change in its document.

Documents for existing code
`litmus adopt` makes a document from files that have none, split at their
declarations. The steps are in the skill litmus-document, which `litmus init`
installs: adopt, check, propose an outline and wait for the user, write each
chapter in the style of the brief, check after each, and render.

If untangle reports a line it cannot place, the line lost the indent of its
excerpt: fix it in the tangled file and run untangle again. If it says that the
documents changed too, run `litmus sync`, and if that stops as well, ask the user.
If tangle refuses because a file changed since it was tangled, the change is not
in the documents yet: run untangle (step 2), then check.

# Making a literate document with Litmus

A literate document explains code in prose, with the code in the order that explains it
best. Litmus keeps the document and the code equal: tangling the document gives the code
byte for byte. Run `litmus guide` first if you have not; it says how a Litmus project works.
Use the Litmus command that AGENTS.md names, or `litmus`.

## The brief

The user gives a brief: a Markdown file with these sections.

- `## Files`: files and folders, relative to the code's directory, one per line. Or a
  command that lists them, such as `git diff --name-only A..HEAD`.
- `## Goal`: why the user wants the document. Aim the explanation at it.
- `## Reader and style`: who reads the document, and how prose and pictures are done.
- `## Settings`: optional `key: value` lines for the weave, such as `mermaid-theme: neutral`.
- `## Output`: `document:` the path of the new document; `code:` the code's directory;
  `kind:` `owned` (the document lives with the code and owns it) or `companion` (the
  document is for reading, lives anywhere, and never writes to the code).

If the brief is missing something, ask the user before you start.

## Steps

1. Read the brief. Expand its folders, or run its command, to get the list of files.
   If the list is long, show it to the user.
2. Make the skeleton:
   `litmus adopt -o CODE [--companion] --style BRIEF DOCUMENT FILES...`
   where BRIEF is the brief's path relative to the document. Then run
   `litmus check -o CODE DOCUMENT`. It must pass.
3. Read the code. Propose an outline: the chapters, the order that explains the code
   best, and the pictures each chapter needs. Write it in the conversation, and stop.
   Do not write prose until the user agrees.
4. For each chapter, in the style of the brief:
   - Move the excerpt blocks into the order of the outline. A block moves with its
     label, the `… name :file: path` line above it. Never change a line of code, and
     never change a label.
   - Write prose before each block: what it does, then why. Lead with the idea, then the
     detail. Use the names the code uses.
   - Add pictures where the style asks: Mermaid diagrams in `++++` passthrough blocks
     as `<pre class="mermaid">`, and animations as small scripts.
   - Code that only illustrates goes in a block with no label. It is shown, never tangled.
   - Run `litmus check -o CODE DOCUMENT` after each chapter. It must pass.
5. Render the document with the project's build for documents, or `asciidoctor`, and ask
   the user to read it.

## While the code moves

For a document that stays in use, run `litmus watch -o CODE DOCUMENT` in the background
and read what it prints. Every block of its output ends with a `next:` line that says what
to do: usually, write prose for the blocks that grew, in the style of the brief.

## Never

- change the code of a companion document's code directory;
- edit `.litmus/map`;
- start a line of code with `…` (U+2026);
- use `--force` unless the user asks.
