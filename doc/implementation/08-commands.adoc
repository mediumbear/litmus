== The Commands

:litmus-dir: src

Everything so far was a stage. This chapter puts the stages together into the commands of the spec:

`litmus tangle [-o DIR] [--force] DOCUMENT...`::
Loads the document set, resolves and checks it, tangles, and writes the files and the map.

`litmus check [-o DIR] DOCUMENT...`::
Tangles in memory and compares the result with the files on disk. This is the round-trip check that an agent runs after every change.

`litmus where [-o DIR] FILE:LINE`::
Looks a line up in the map.

`litmus guide`::
Prints the guide for agents.

`litmus init [-o DIR] DOCUMENT...`::
Prepares a project so that agents find the guide.

`litmus untangle [-o DIR] [-f FILE]... [--force] DOCUMENT...`::
Carries changes in the tangled files back into the documents.

`litmus sync [-o DIR] DOCUMENT...`::
Does whichever of tangle and untangle is needed.

`litmus watch [-o DIR] [--interval MS] DOCUMENT...`::
Runs sync now, and again whenever a file changes.

`main.zig` reads the command line and runs the right command. `compare.zig` is the comparison that `check` makes, and `init.zig` is init. The text of the guide is a file of its own, which the program carries inside it.

The options are `-o DIR`, `--force` for tangle and untangle, and `-f FILE` for untangle (U8), and `--interval MS` for watch (W3). Each command says which of them it takes, in an `Allowed` value. Anything else that starts with a hyphen is an error, and the rest are the positional arguments: documents, or the `FILE:LINE` of `where`. `parseOptions` prints the problem itself and returns null, and the caller exits with 2.

const Options = struct {
    out_dir: []const u8 = ".",
    force: bool = false,
    /// The files named with `-f` (U8).
    files: []const []const u8 = &.{},
    /// How often watch looks at the files, in milliseconds (W3).
    interval_ms: u64 = 200,
    positional: []const []const u8 = &.{},
};

/// Which options a command takes besides `-o DIR`.
const Allowed = struct { force: bool = false, files: bool = false, interval: bool = false };

/// Reads `-o DIR`, and `--force` and `-f FILE` when allowed. Prints the problem and returns
/// null on a usage error.
fn parseOptions(ctx: Context, args: []const []const u8, allowed: Allowed) !?Options {
    var options: Options = .{};
    var positional: std.ArrayList([]const u8) = .empty;
    var files: std.ArrayList([]const u8) = .empty;
    var i: usize = 0;
    while (i < args.len) : (i += 1) {
        const arg = args[i];
        if (std.mem.eql(u8, arg, "-o")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: -o needs a directory\n");
                return null;
            }
            options.out_dir = args[i];
        } else if (allowed.force and std.mem.eql(u8, arg, "--force")) {
            options.force = true;
        } else if (allowed.interval and std.mem.eql(u8, arg, "--interval")) {
            i += 1;
            const milliseconds = if (i < args.len) std.fmt.parseInt(u64, args[i], 10) catch 0 else 0;
            if (milliseconds == 0) {
                try ctx.err.writeAll("litmus: --interval needs a number of milliseconds\n");
                return null;
            }
            options.interval_ms = milliseconds;
        } else if (allowed.files and std.mem.eql(u8, arg, "-f")) {
            i += 1;
            if (i == args.len) {
                try ctx.err.writeAll("litmus: -f needs a file\n");
                return null;
            }
            try files.append(ctx.arena, args[i]);
        } else if (arg.len > 1 and arg[0] == '-') {
            try ctx.err.print("litmus: unknown option {s}\n", .{arg});
            return null;
        } else {
            try positional.append(ctx.arena, arg);
        }
    }
    options.positional = positional.items;
    options.files = files.items;
    return options;
}

`build` is shared by tangle, check and the commands built on them: load, resolve, tangle. `buildInto` also gives back the documents that were found, even when there are errors, which watch needs in order to know what to watch (W2). If any stage reports a problem, the diagnostics are sorted, printed, and `null` is returned. When the loading stage has found problems, the checks of the whole set are not run, because they would be answers about a set that was read wrongly: a label that failed to parse would make its excerpt unused, and so on.

    docs: []const types.Document,
    files: []const tangle.Tangled,

fn printDiagnostics(ctx: Context, diags: *types.Diagnostics, docs: []const types.Document) !void {
    diags.sort();
    for (diags.list.items) |d| {
        const path = docs[d.doc].path;
        if (d.line == 0) {
            try ctx.err.print("{s}: {s}\n", .{ path, d.message });
        } else {
            try ctx.err.print("{s}:{d}: {s}\n", .{ path, d.line, d.message });
        }
    }
}

/// Loads, checks and tangles the document set. On errors it prints them and returns null.
fn build(ctx: Context, documents: []const []const u8) !?Built {
    return buildInto(ctx, documents, null);
}

/// Like `build`, and gives the documents that were found even when there are errors, which
/// watch needs to know what to watch.
fn buildInto(ctx: Context, documents: []const []const u8, found: ?*[]const types.Document) !?Built {
    var diags = types.Diagnostics.init(ctx.arena);
    var fs: DiskFs = .{ .io = ctx.io };
    const set = try docset.load(ctx.arena, &fs, documents, &diags);
    if (found) |out| out.* = set.docs;
    // Mistakes in the structure make the checks of the whole set misleading.
    if (diags.list.items.len == 0) {
        const resolved = try resolve.resolve(ctx.arena, set.docs, set.blocks, &diags);
        if (diags.list.items.len == 0) {
            return .{ .docs = set.docs, .files = try tangle.tangleAll(ctx.arena, resolved) };
        }
    }
    try printDiagnostics(ctx, &diags, set.docs);
    return null;
}

`untangle` carries the changes made in the tangled files back into the documents. The work is done by chapter 9, which plans the edits, applies them and checks the result. The command's part is to make sure it is safe, to do the writing, and to report.

It begins like `check`: the document set is built, and the output directory is opened.

Untangle's base is the documents tangled in memory (U1). That is right only if the documents' code is what tangle last wrote. If it is not, the documents changed too, and the differences between the files and the base would partly be the documents' own edits, which untangle would take back. So the tangled text of every file is compared with the hash in the map, and any difference stops the command (U1, U7). Without a map nothing can be known, and that stops it too. `--force` skips this, for the writer who knows the documents did not change.

`syncOnce` is one run of sync. It decides which way to go, as the spec's U7 says, and then runs `untangle` or `tangle` itself, with the same arguments. The decision is made by `sync.zig`, which compares hashes. This function gathers them. It gives back an exit code and the list of files that a watcher has to look at: the documents of the set, and the tangled files (W2).

/// One run of sync (U7). `args` are the arguments of the command, which tangle and untangle read again.
fn syncOnce(ctx: Context, options: Options, args: []const []const u8) !SyncResult {
    var found: []const types.Document = &.{};
    const built = (try buildInto(ctx, options.positional, &found)) orelse {
        return .{ .code = 1, .watched = try watchedPaths(ctx, options, found, &.{}) };
    };

=== Watch

`watch` keeps the documents and the files in step while the writer works (W1 to W5). It does not decide anything about the files itself. It decides _when_, and then asks sync.

++++
<pre class="mermaid">
flowchart TD
  start([litmus watch]) --> run[Run sync once]
  run --> look[Look at every watched file again<br/>so that what sync wrote is not a change]
  look --> sleep[Sleep one interval]
  sleep --> poll[Look at every watched file]
  poll --> moved{Did anything change<br/>since the last look?}
  moved -- no --> quiet{Was there a change before,<br/>and is it quiet for one interval now?}
  moved -- yes --> restart[Start waiting again]
  restart --> sleep
  quiet -- no --> sleep
  quiet -- yes --> run
</pre>
++++

Two things in the picture are rules of the spec. After a run, the files are looked at again before waiting (W4), so Litmus's own writes are never taken for the writer's. And a run that stops, because both sides changed or a document has an error, is not repeated: the loop goes back to sleep, and only a new change wakes it (W5).

The waiting is the part that is easy to get wrong, so here it is run on a small example. A writer saves three times in a row, and once more later. Each dot is a look at the files. Step through it.

The functions that look at files and compare the looks are in `watch.zig`, which is small enough to show whole.

What watch remembers between looks is a `Seen`: the paths it watches, and what it saw of them. A path list and a snapshot are made together in one arena of their own, because both are replaced after every run, and a program that runs for hours must not keep every run's memory. The documents of the set may change from one run to the next (W2), so the paths are copied out of the run's arena before it is freed. `seconds` is the time since the start, for the heading of each run.

… Seen :file: main.zig
[source,zig]

/// What watch remembers between looks: the files it watches and what it saw of them. It
/// owns an arena, which is replaced as a whole.
const Seen = struct {
    arena: std.heap.ArenaAllocator,
    paths: []const []const u8,
    snapshot: watch.Snapshot,

    fn take(io: Io, paths: []const []const u8) !Seen {
        var arena = std.heap.ArenaAllocator.init(std.heap.page_allocator);
        errdefer arena.deinit();
        const copies = try arena.allocator().alloc([]const u8, paths.len);
        for (paths, copies) |path, *copy| copy.* = try arena.allocator().dupe(u8, path);
        return .{ .arena = arena, .paths = copies, .snapshot = try watch.take(io, arena.allocator(), copies) };
    }

    fn deinit(self: *Seen) void {
        self.arena.deinit();
    }
};

fn seconds(io: Io, since: Io.Timestamp) f64 {
    const ns = since.durationTo(Io.Timestamp.now(io, .awake)).nanoseconds;
    return @as(f64, @floatFromInt(ns)) / 1e9;
}

The waiting. Every interval each watched file is looked at, and compared with the look before (W3). The first look after a run is compared with the one made just after the run, so a save during the run is not lost. The debounce is told whether anything changed (W1). /// Looks at each path, relative to the current directory. A path that cannot be
/// looked at is a file that does not exist.
pub fn take(io: Io, arena: Allocator, paths: []const []const u8) Allocator.Error!Snapshot {
    const entries = try arena.alloc(Entry, paths.len);
    for (paths, entries) |path, *entry| {
        entry.* = .{ .path = path };
        const stat = Io.Dir.cwd().statFile(io, path, .{}) catch continue;
        entry.exists = true;
        entry.size = stat.size;
        entry.mtime = stat.mtime.nanoseconds;
    }
    return .{ .entries = entries };
}

`changed` compares two snapshots and names the paths that differ. A path that is in only one of the snapshots counts as a change, so a new include, or a tangled file that has just been made, shows up.

… changed :file: watch.zig
[source,zig]
----
/// The paths whose existence, size or modification time differ between two snapshots
/// (W3). A path that is in only one of them is a change.
pub fn changed(arena: Allocator, old: Snapshot, new: Snapshot) Allocator.Error![]const []const u8 {
    var result: std.ArrayList([]const u8) = .empty;
    var seen: std.StringHashMapUnmanaged(Entry) = .empty;
    for (old.entries) |entry| try seen.put(arena, entry.path, entry);
    for (new.entries) |entry| {
        const before = seen.get(entry.path) orelse {
            try result.append(arena, entry.path);
            continue;
        };
        _ = seen.remove(entry.path);
        if (before.exists != entry.exists or before.size != entry.size or before.mtime != entry.mtime) {
            try result.append(arena, entry.path);
        }
    }
    for (old.entries) |entry| {
        if (seen.contains(entry.path)) try result.append(arena, entry.path);
    }
    return result.items;
}

The debounce is a small state machine and takes the time as a number, so it can be tested without waiting. Every look tells it whether anything changed. A change starts the wait, and any further change starts it again. When a look finds nothing changed and the time since the last change has reached the quiet time, `observe` returns true, once. That is the moment for a run (W1).

… Debounce :file: watch.zig
[source,zig]
----
/// W1: a change starts a wait, every further change starts it again, and the files are
/// ready to be acted on when nothing changed for `quiet` nanoseconds.
pub const Debounce = struct {
    quiet: i64,
    last_change: ?i64 = null,

    /// Tells the debounce what one look found, and the time of it. Returns true once, when
    /// the files have been quiet for long enough after a change.
    pub fn observe(self: *Debounce, found_change: bool, now: i64) bool {
        if (found_change) {
            self.last_change = now;
            return false;
        }
        const last = self.last_change orelse return false;
        if (now - last < self.quiet) return false;
        self.last_change = null;
        return true;
    }
};

/// The line `n` of a text, counting from 1, without its `\n`; null past the end.
fn lineOf(text: []const u8, n: u32) ?[]const u8 {
    var start: usize = 0;
    var i: u32 = 1;
    while (i < n) : (i += 1) {
        start = (std.mem.indexOfScalarPos(u8, text, start, '\n') orelse return null) + 1;
    }
    if (start >= text.len) return null;
    const end = std.mem.indexOfScalarPos(u8, text, start, '\n') orelse text.len;
    return text[start..end];
}

fn compareFile(docs: []const types.Document, file: tangle.Tangled, text: []const u8) !Difference {
    const common = std.mem.indexOfDiff(u8, file.text, text) orelse unreachable;
    const line: u32 = @intCast(std.mem.countScalar(u8, file.text[0..common], '\n') + 1);
    var difference: Difference = .{
        .path = file.path,
        .kind = .differs,
        .line = line,
        .expected = lineOf(file.text, line),
        .found = lineOf(text, line),
    };
    // A difference past the end of the tangled text is reported at its last run.
    if (map.findRun(file.runs, line)) |at| {
        const run = file.runs[at];
        difference.origin = .{ .doc = docs[run.doc].path, .line = run.doc_line + (line - run.line), .excerpt = run.excerpt };
    } else if (file.runs.len > 0) {
        const run = file.runs[file.runs.len - 1];
        difference.origin = .{ .doc = docs[run.doc].path, .line = run.doc_line + run.count - 1, .excerpt = run.excerpt };
    }
    return difference;
}

----
/// Compares each tangled file with the file of the same path under `dir`.
pub fn compare(io: Io, arena: Allocator, dir: Io.Dir, docs: []const types.Document, files: []const tangle.Tangled) ![]const Difference {
    var result: std.ArrayList(Difference) = .empty;
    for (files) |file| {
        const text = try output.readOrNull(io, arena, dir, file.path) orelse {
            try result.append(arena, .{ .path = file.path, .kind = .missing });
            continue;
        };
        if (!std.mem.eql(u8, text, file.text)) {
            try result.append(arena, try compareFile(docs, file, text));
        }
        if (comptime Io.File.Permissions.has_executable_bit) {
            const stat = try dir.statFile(io, file.path, .{});
            if (output.isExecutable(stat.permissions) != file.executable) {
                try result.append(arena, .{
                    .path = file.path,
                    .kind = if (file.executable) .should_be_executable else .should_not_be_executable,
                });
            }
        }
    }
    return result.items;
}

/// The text with a final `\n`, and `addition` after it.
fn appended(arena: Allocator, existing: []const u8, addition: []const u8) ![]const u8 {
    const newline: []const u8 = if (existing.len > 0 and existing[existing.len - 1] != '\n') "\n" else "";
    return std.mem.concat(arena, u8, &.{ existing, newline, addition });
}

/// Finds a line of `text` that equals `marker` once trimmed: the offset of its start and of its end, past the `\n`.
fn findLine(text: []const u8, marker: []const u8, from: usize) ?struct { start: usize, end: usize } {
    var start = from;
    while (start < text.len) {
        const newline = std.mem.indexOfScalarPos(u8, text, start, '\n');
        const end = if (newline) |n| n + 1 else text.len;
        const line = std.mem.trim(u8, text[start..end], " \t\r\n");
        if (std.mem.eql(u8, line, marker)) return .{ .start = start, .end = end };
        start = end;
    }
    return null;
}

=== AGENTS.md

`applyAgents` makes the new text of `AGENTS.md` (I1). If the file has the paragraph already, it is replaced in place, so the text around it stays as it was. If it has not, the paragraph is added at the end, after a blank line. A file with the opening comment and no closing one is an error, because replacing something with no end would mean guessing.

A file that comes out the same as it was returns null, which is how a second run changes nothing (I4).

/// The new text of AGENTS.md (I1), or null when it stays as it is.
pub fn applyAgents(arena: Allocator, existing: ?[]const u8, para: []const u8) AgentsError!?[]const u8 {
    const text = existing orelse return para;
    var result: []const u8 = undefined;
    if (findLine(text, start_marker, 0)) |start| {
        const end = findLine(text, end_marker, start.end) orelse return error.UnclosedParagraph;
        result = try std.mem.concat(arena, u8, &.{ text[0..start.start], para, text[end.end..] });
    } else {
        result = try appended(arena, text, if (text.len > 0) try std.mem.concat(arena, u8, &.{ "\n", para }) else para);
    }
    return if (std.mem.eql(u8, result, text)) null else result;
}

=== Running init

`run` handles the three files in turn. It reads each, computes the new text, and writes it whole if there is any, saying `created` or `updated`. An error in one file does not stop the others, and makes the exit code 1.

/// Runs init in the current directory, printing each change to `out`. Returns the exit code.
pub fn run(io: Io, arena: Allocator, args: Args, out: *Io.Writer, err: *Io.Writer) !u8 {
    const cwd = Io.Dir.cwd();
    const entry = try ignoreEntry(arena, args.dir);
    const para = try paragraph(arena, args);
    var failed = false;

    const names = [_][]const u8{ "AGENTS.md", "CLAUDE.md", ".gitignore" };
    for (names) |name| {
        const existing = try output.readOrNull(io, arena, cwd, name);
        const updated: ?[]const u8 = if (std.mem.eql(u8, name, "AGENTS.md"))
            applyAgents(arena, existing, para) catch |e| switch (e) {
                error.UnclosedParagraph => {
                    try err.print("{s}: has \"{s}\" but no \"{s}\" after it\n", .{ name, start_marker, end_marker });
                    failed = true;
                    continue;
                },
                else => return e,
            }
        else if (std.mem.eql(u8, name, "CLAUDE.md"))
            try applyClaude(arena, existing)
        else
            try applyGitignore(arena, existing, entry);
        const text = updated orelse continue;
        try output.writeAtomic(io, cwd, name, text, false);
        try out.print("{s} {s}\n", .{ if (existing == null) "created" else "updated", name });
    }
    return if (failed) 1 else 0;
}

=== The guide

The guide is what `litmus guide` prints. Agents read it before they change a tangled file. It tells them how to find their way (`.litmus/map`, `litmus where`), how to change code so that the documents and the files stay equal, and what never to do. Changing code now goes through untangle: the agent edits and tests the tangled file, runs untangle, writes the prose it asks for, and checks. If watch is running, it does the untangling on every save, and the agent only has to read its output. The guide also says what to do when untangle cannot place a line, or finds that the documents changed too. It is written for an agent, in plain words and short sentences.

----
Litmus: a guide for agents

Some files in this project are tangled. Their code lives in documents, asciidoc or
Markdown, that explain it. A tangled file must always equal what its documents
tangle to. AGENTS.md gives this project's commands for tangle and check.

Finding your way
- .litmus/map lists every tangled file: each line starting with "file" names one.
- `litmus where FILE:LINE` prints the document line, and the excerpt, that a line
  of a tangled file came from. It works for lines in compiler errors too.
- A document labels each block of code with the file it lands in:
  `… name :file: path` for an excerpt, `… :file: path` for the start of a file.
  Inside a block, a line `… name` inserts that excerpt, at that indent.

Changing code
1. Edit the tangled file and test it as usual.
2. Run the untangle command from AGENTS.md. It carries the change into the
   document's blocks, and lists the blocks that need prose.
3. Write the prose for every block it lists: what the new code does and why.
   If new code deserves a block of its own, put it in one, labeled with its name
   and file and inserted by exactly one `… name` line.
4. Run the check command from AGENTS.md. The change is done only when it passes.

If `litmus watch` is running in this project, it does step 2 by itself whenever a
file is saved. Read its output: it still lists the blocks that need prose.

Never
- edit .litmus/map;
- run `litmus tangle --force` or `litmus untangle --force` unless the user asks:
  they skip the protection of edits;
- start a line of code with `…` (U+2026);
- leave a tangled file changed without the same change in its document.

If untangle reports a line it cannot place, the line lost the indent of its
excerpt: fix it in the tangled file and run untangle again. If it says that the
documents changed too, run `litmus sync`, and if that stops as well, ask the user.
If tangle refuses because a file changed since it was tangled, the change is not
in the documents yet: run untangle (step 2), then check.
