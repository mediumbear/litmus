== Parsing

:litmus-dir: src

The parser reads one scanned document and finds what Litmus is about: the labeled blocks, the excerpt commands inside them, the `include::` lines, and the directory entry. It turns a stream of line kinds into the `Block`, `Label` and `Command` values of chapter 1.

It reports every problem it finds, as a diagnostic, and goes on. A writer with three mistakes in a chapter should see three messages. When a label is wrong, the block that follows it is treated as an illustration, so that one mistake does not set off many more.

The parser does no IO. It is given a `Document` and returns blocks whose lines are slices of the document's own lines.

The parser is one file: small functions for paths and labels, and one larger function, `parse`, which is a loop over the lines of the document.

Its result has two parts. A document's blocks are in order, and so are its `include::` lines, each with the line it is on. The document set (chapter 4) merges the two, so that an included document's blocks land at the include's place in the reading order (L6).

`blank` is what separates the words of a label. It includes `\r`, so that a document with Windows line ends does not leave a carriage return on a name.

=== Paths

A path appears in a label (L1), in the directory entry (L8), and nowhere else. It is relative, written with `/`, and has no `..` parts and no empty parts. It may not hold a tab, because the map separates its fields with tabs. A `.` part is allowed and is dropped, so `./a/./b` is `a/b`.

`pathProblem` says why a path is wrong, in words for the message, or returns null if it is fine. `normalizePath` drops the `.` parts of a path that passed, allocating only when there is something to drop.

/// Why a path breaks L1, or null if it is fine.
pub fn pathProblem(path: []const u8) ?[]const u8 {
    if (path.len == 0) return "the path is empty";
    if (path[0] == '/') return "the path must be relative";
    if (std.mem.indexOfScalar(u8, path, '\t') != null) return "the path has a tab";
    var parts = std.mem.splitScalar(u8, path, '/');
    var real_parts: usize = 0;
    while (parts.next()) |part| {
        if (part.len == 0) return "the path has an empty part";
        if (std.mem.eql(u8, part, "..")) return "the path has a '..' part";
        if (!std.mem.eql(u8, part, ".")) real_parts += 1;
    }
    if (real_parts == 0) return "the path is empty";
    return null;
}

/// Removes the `.` parts of a path that `pathProblem` accepted.
pub fn normalizePath(arena: Allocator, path: []const u8) ![]const u8 {
    if (std.mem.indexOf(u8, path, "./") == null and !std.mem.endsWith(u8, path, "/.")) return path;
    var out: std.ArrayList(u8) = .empty;
    var parts = std.mem.splitScalar(u8, path, '/');
    while (parts.next()) |part| {
        if (std.mem.eql(u8, part, ".")) continue;
        if (out.items.len > 0) try out.append(arena, '/');
        try out.appendSlice(arena, part);
    }
    return out.items;
}

=== Labels

A document command is `… name :file: path`, or `… :file: path` for the root of a file, and may end with `:executable:` (L1, L9). The text after the ellipsis is cut into words at blanks. A word that begins and ends with a colon is an attribute. `:file:` and `:executable:` are the ones that mean something; any other is C11.

Only whole words count, so `a:file:b` is part of a name. The name is the text before `:file:`, trimmed, and may hold spaces. The path is the text after `:file:`, up to the next attribute.

`parseLabel` reads the whole text and reports what it finds wrong, C11 for the shape and C7 for the path. It returns null for any label that is broken, so that the caller drops the label.

const ParsedLabel = struct { name: ?[]const u8, path: []const u8, executable: bool };

fn isAttribute(word: []const u8) bool {
    return word.len >= 3 and word[0] == ':' and word[word.len - 1] == ':';
}

/// Reads the text of a document command (L1, L9). Reports C11 and C7 itself.
fn parseLabel(diags: *Diagnostics, doc: u32, line: u32, text: []const u8) !?ParsedLabel {
    var file_at: ?usize = null; // where the text after `:file:` starts
    var file_start: usize = 0;
    var path_end: usize = text.len;
    var executable = false;
    var ok = true;
    var i: usize = 0;
    while (i < text.len) {
        while (i < text.len and std.mem.indexOfScalar(u8, blank, text[i]) != null) i += 1;
        const start = i;
        while (i < text.len and std.mem.indexOfScalar(u8, blank, text[i]) == null) i += 1;
        const word = text[start..i];
        if (!isAttribute(word)) continue;
        … label attributes
    }
    const at = file_at orelse {
        if (ok) try diags.add(doc, line, "C11: the label has no :file:", .{});
        return null;
    };
    if (!ok) return null;
    … label name and path
    return .{ .name = if (name.len == 0) null else name, .path = path, .executable = executable };
}
----

Each attribute word is checked as it is found. `:file:` is remembered, with where the path starts, and a second one is an error. `:executable:` is only meaningful after `:file:`. Any attribute ends the path, so the path of `a :file: x.zig :executable:` is `x.zig`.

An `include::` line (L6) has a path up to the first `[`. The path must not be empty or absolute, and may not hold a tab. Anything else about the line, such as its options, does not matter to Litmus.

… includePath :file: parse.zig
[source,zig]
----
/// Reads the path of an `include::path[...]` line (L6).
fn includePath(line: []const u8) ?[]const u8 {
    const rest = line["include::".len..];
    const open = std.mem.indexOfScalar(u8, rest, '[') orelse return null;
    if (open == 0 or rest[0] == '/') return null;
    if (std.mem.indexOfScalar(u8, rest[0..open], '\t') != null) return null;
    return rest[0..open];
}

=== The parse loop

`parse` walks the lines once. For every line it asks the scanner for the kind, and keeps a small amount of state about the document:

… parse :file: parse.zig
[source,zig]
----
pub fn parse(arena: Allocator, doc_index: u32, doc: Document, diags: *Diagnostics) !Parsed {
    var scanner = scan.Scanner.init(doc.format);
    var blocks: std.ArrayList(Block) = .empty;
    var includes: std.ArrayList(Include) = .empty;

    … parse state

    for (doc.lines, 0..) |line, index| {
        const n: u32 = @intCast(index + 1);
        const kind = scanner.next(line);
        switch (kind) {
            .attribute, .title => continue,
            … a block opens
            … a line of code
            … a block closes
            .prose, .skip, .command, .include, .dir => {},
        }
        … a label waits for its block
        switch (kind) {
            … a document command
            … an include line
            … a directory entry
            else => {},
        }
    }
    … the end of the document
    return .{ .blocks = try blocks.toOwnedSlice(arena), .includes = try includes.toOwnedSlice(arena) };
}
----

The directory entry applies to the whole document, so it is remembered (L8). `dir_seen` and `command_seen` are for C8: the entry may come once, and before the first document command.

A document command waits in `pending` until the next block opens and takes it. While a block is open, `block_label` holds its label, or null for an illustration, and `commands` collects its excerpt commands.

Inside a labeled block, a line that is a Litmus command is an excerpt command (L4). Its position in the block, its indent and its name are recorded. The name is trimmed, so that a stray space or `\r` does not change which excerpt it means.

An `include::` line inside a labeled block is C7: Asciidoctor would paste the file into the block on the page, but tangle would not, and the page and the code would differ.

=== Tests

The parser's tests build a document from a string, parse it, and look at the blocks or at the diagnostics. Each one names its rule. A diagnostic is found by its line and a piece of its message, so the tests do not repeat whole messages.

`Result` holds the parse and its diagnostics, and checks for a message at a line, or for none at all.

… test helpers :file: parse.zig
[source,zig]
----
// Tests ----------------------------------------------------------------------

const t = std.testing;

const Result = struct {
    parsed: Parsed,
    diags: Diagnostics,

    fn expectDiag(self: Result, line: u32, needle: []const u8) !void {
        for (self.diags.list.items) |d| {
            if (d.line == line and std.mem.indexOf(u8, d.message, needle) != null) return;
        }
        std.debug.print("no diagnostic at line {d} with \"{s}\"; have:\n", .{ line, needle });
        for (self.diags.list.items) |d| std.debug.print("  {d}: {s}\n", .{ d.line, d.message });
        return error.MissingDiagnostic;
    }

    fn expectNoDiags(self: Result) !void {
        if (self.diags.list.items.len != 0) {
            for (self.diags.list.items) |d| std.debug.print("  {d}: {s}\n", .{ d.line, d.message });
        }
        try t.expectEqual(0, self.diags.list.items.len);
    }
};

fn run(arena: Allocator, format: types.Format, text: []const u8) !Result {
    var diags = Diagnostics.init(arena);
    const doc: Document = .{ .path = "d", .format = format, .lines = try scan.splitLines(arena, text), .dir = "" };
    const parsed = try parse(arena, 0, doc, &diags);
    return .{ .parsed = parsed, .diags = diags };
}
