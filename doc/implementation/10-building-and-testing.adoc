== Building and Testing

The last chapter holds what builds Litmus and tests it. These files are not in `src/`, so this chapter sets no directory, and every label gives the whole path.

There are three kinds of test:

Unit tests::
Zig tests in the source files, next to the code they check. `zig build test` runs them. Each names the rule of the spec that it checks.

Golden tests::
Small documents in `test/cases`, with the files and messages that tangling them must give. `zig build cases` tangles each one, checks the result, changes a byte to see that `check` finds it, and asks `where` about every run. They cover every rule and every check of the spec, init, and untangle. They are plain files, not part of this book, since they are data and not code to explain.

The self test::
`zig build self` is the proof that this book is Litmus. It tangles the book into an empty directory, builds a Litmus from that directory and runs its tests, and with that Litmus tangles the book again. The files must equal the repository's, byte for byte, both times. The book describes the program that tangles it, and the program tangles the book.

In everyday work, `zig build test` is the check that the book and the files agree. It also runs `litmus check` on the book. A change to the code means the same change in the block that holds it, and `check` says on which line they differ.

The script stops on unset variables. Failures are counted and printed, and not fatal, so a run shows every case that is wrong. Each case works in a directory made for it, which is removed at the end.

… setup :file: test/run.sh
[source,bash]
----
#!/usr/bin/env bash
# The golden tests and the self-hosting test of Litmus.
#   test/run.sh cases LITMUS   tangles, checks and queries every case in test/cases
#   test/run.sh self LITMUS    tangles the book, builds Litmus from the result, and tangles again
set -u
mode=${1:?usage: test/run.sh cases|self LITMUS}
litmus=$(cd "$(dirname "${2:?usage: test/run.sh cases|self LITMUS}")" && pwd)/$(basename "$2")
root=$(cd "$(dirname "$0")/.." && pwd)
work=$(mktemp -d)
trap 'rm -rf "$work"' EXIT
failures=0

fail() {
  echo "FAIL $1: $2"
  failures=$((failures + 1))
}

# expect_same NAME ACTUAL EXPECTED: two files or trees must be equal.
expect_same() {
  if ! diff -r -x .DS_Store "$2" "$3" > "$work/diff" 2>&1; then
    fail "$1" "differs from the expected result"
    sed 's/^/    /' "$work/diff" | head -20
  fi
}

=== Golden cases

A case with a file `cmd` is an init case, and one with a directory `edit` is an untangle case. The others tangle. A small function runs the command of an init case, with Litmus reachable under the name the command uses: on the `PATH`, or at a relative path such as `tools/litmus` (I1).

… run_init :file: test/run.sh
[source,bash]
----
# Runs the command of an init case in the sandbox, with Litmus reachable under the
# name the command uses: on the PATH, or at a relative path such as tools/litmus.
run_init() {
  local sandbox=$1 cmd=$2 first=${2%% *}
  rm -rf "$work/bin" && mkdir -p "$work/bin"
  if [[ $first == */* ]]; then
    mkdir -p "$sandbox/$(dirname "$first")"
    ln -s "$litmus" "$sandbox/$first"
  else
    ln -s "$litmus" "$work/bin/$first"
  fi
  (cd "$sandbox" && PATH="$work/bin:$PATH" sh -c "$cmd") > "$work/stdout" 2> "$work/stderr"
  local code=$?
  if [[ $first == */* ]]; then
    rm "$sandbox/$first"
    (cd "$sandbox" && rmdir -p "$(dirname "$first")" 2> /dev/null)
  fi
  return $code
}

An untangle case has a directory `edit`, which holds changed copies of the tangled files. The documents are tangled into the output directory first, or the output starts as `before`, which is how the cases for a stale map or no map are made. Then the files of `edit` are copied over the output, as a writer's edits would be, and the files named in `remove` are removed. Untangle must give the documents in `expected`, and say what `expected.out` and `expected.err` say. When it succeeds, `check` must pass on the result, and a second untangle must find nothing to do. The documents are copied into a sandbox first, since untangle changes them.

… untangle_case :file: test/run.sh
[source,bash]
----
# A case with an `edit` directory is an untangle case. The documents are tangled into the
# output, or the output starts as `before`. Then the files of `edit` are copied over the
# output, those named in `remove` are removed, and untangle has to give the documents
# in `expected`. Options for untangle go in `options`.
untangle_case() {
  local dir=$1 name=$2 sandbox=$work/sandbox out=$work/out args options="" want_exit=0 code path
  rm -rf "$sandbox" "$out" && mkdir -p "$sandbox" "$out"
  cp -R "$dir/." "$sandbox/"
  (cd "$sandbox" && rm -rf edit expected before remove expected.out expected.err args exit options)
  [ -f "$dir/exit" ] && want_exit=$(cat "$dir/exit")
  [ -f "$dir/options" ] && options=$(cat "$dir/options")
  args=$(cat "$dir/args")
  if [ -d "$dir/before" ]; then
    cp -R "$dir/before/." "$out/"
  else
    (cd "$sandbox" && "$litmus" tangle -o "$out" $args) > /dev/null 2>&1 || fail "$name" "the documents do not tangle"
  fi
  cp -R "$dir/edit/." "$out/"
  [ -f "$dir/remove" ] && while read -r path; do rm -f "$out/$path"; done < "$dir/remove"
  (cd "$sandbox" && "$litmus" untangle -o "$out" $options $args) > "$work/stdout" 2> "$work/stderr"
  code=$?
  [ "$code" -eq "$want_exit" ] || fail "$name" "untangle exited $code, not $want_exit"
  expect_same "$name (the documents)" "$sandbox" "$dir/expected"
  expect_same "$name (what untangle prints)" "$work/stdout" "$( [ -f "$dir/expected.out" ] && echo "$dir/expected.out" || echo /dev/null )"
  expect_same "$name (what untangle says)" "$work/stderr" "$( [ -f "$dir/expected.err" ] && echo "$dir/expected.err" || echo /dev/null )"
  [ "$want_exit" -eq 0 ] || return
  # The documents tangle to the files, and a second untangle has nothing to do. A file that
  # was removed stays missing.
  [ -f "$dir/remove" ] || (cd "$sandbox" && "$litmus" check -o "$out" $args) > /dev/null 2> "$work/stderr" || fail "$name" "check failed after untangle: $(cat "$work/stderr")"
  (cd "$sandbox" && "$litmus" untangle -o "$out" $options $args) > "$work/stdout" 2> /dev/null
  [ "$(head -n 1 "$work/stdout")" = "nothing to untangle" ] || fail "$name" "the second untangle said: $(cat "$work/stdout")"
}
----

A case that has a file `cmd` runs that command: init, adopt, or a few commands in a row, such as an adopt followed by an untangle of a companion. Only init is run twice, since running it twice must change nothing (I4). The command is run in a sandbox that holds the files of `before`, with Litmus available under the name the command uses: on the `PATH`, or at a relative path such as `tools/litmus` (I1). The sandbox must then equal `expected`, and the second run has to print nothing and change nothing (I4).

… init_case :file: test/run.sh
[source,bash]
----
# A case with a `cmd` file runs that command: init, adopt, or a few commands in a row.
# The others are tangle cases.
init_case() {
  local dir=$1 name=$2 sandbox=$work/sandbox cmd
  rm -rf "$sandbox" && mkdir -p "$sandbox"
  [ -d "$dir/before" ] && cp -R "$dir/before/." "$sandbox/"
  cmd=$(cat "$dir/cmd")
  run_init "$sandbox" "$cmd" || fail "$name" "init failed: $(cat "$work/stderr")"
  expect_same "$name (what init prints)" "$work/stdout" "$( [ -f "$dir/expected.out" ] && echo "$dir/expected.out" || echo /dev/null )"
  expect_same "$name (the files)" "$sandbox" "$dir/expected"
  # I4: a second init changes nothing. Other commands run once.
  case " $cmd " in
    *" init "*) ;;
    *) return ;;
  esac
  run_init "$sandbox" "$cmd"
  [ -s "$work/stdout" ] && fail "$name" "the second init printed: $(cat "$work/stdout")"
  expect_same "$name (the files after a second run)" "$sandbox" "$dir/expected"
}

Last, `where` is asked for the first and the last line of every run in the map. The answer has to be the run's document line, moved by how far into the run the line is, and the excerpt's name.

… case, where :file: test/run.sh
[source,bash]
----
# 4. Where: the first and last line of every run.
local file_name=""
while IFS=$'\t' read -r first second third fourth fifth sixth; do
  [ "$first" = "litmus map 1" ] && continue
  if [ "$first" = file ]; then
    file_name=$second
    continue
  fi
  local excerpt=$sixth
  [ "$excerpt" = ":file:" ] && excerpt="file root"
  local last=$((first + second - 1)) doc_last=$((fourth + second - 1))
  [ "$("$litmus" where -o "$out" "$file_name:$first")" = "$third:$fourth ($excerpt)" ] || fail "$name" "where $file_name:$first"
  [ "$("$litmus" where -o "$out" "$file_name:$last")" = "$third:$doc_last ($excerpt)" ] || fail "$name" "where $file_name:$last"
done < "$out/.litmus/map"

`cases` runs every directory of `test/cases`, and picks the function by what the directory holds. Then it runs the watch tests. After the cases it times the tangling of a generated document of 100,000 lines of code, a thousand excerpts of a hundred lines each, and then the untangling of one changed line of the result. The times are printed and not judged, since they depend on the machine and on whether the program is a release build.

… cases :file: test/run.sh
[source,bash]
----
cases() {
  local dir name count=0
  for dir in "$root"/test/cases/*/; do
    dir=${dir%/}
    name=$(basename "$dir")
    count=$((count + 1))
    if [ -f "$dir/cmd" ]; then
      init_case "$dir" "$name"
    elif [ -d "$dir/edit" ]; then
      untangle_case "$dir" "$name"
    else
      tangle_case "$dir" "$name"
    fi
  done
  echo "cases: $count run"
  watch_tests
  speed
}

=== The watch tests

Watch cannot be tested by comparing trees, since it runs until it is stopped. These tests start it, change files as a writer would, and wait for the log to say what happened. `wait_for` polls the log for a line, up to ten seconds, and fails if it is not there. A slow machine is slow, not wrong.

… wait_for :file: test/run.sh
[source,bash]
----
# Waits until the log has at least $3 lines that contain $2, or fails after ten seconds.
wait_for() {
  local log=$1 pattern=$2 want=${3:-1} i
  for i in $(seq 1 200); do
    [ "$(grep -c -F -e "$pattern" "$log")" -ge "$want" ] && return 0
    sleep 0.05
  done
  return 1
}
----

The tests run in order, each one starting from where the one before ended. The log is checked for words that are in sync's messages: `the files changed: untangling` and `the documents changed: tangling`.

# Watch is started in a sandbox with a short interval, the files and documents are changed as
# a writer would change them, and each time the log has to say what happened (W1 to W5).
watch_tests() {

  … watch test, quiet

  … watch test, a tangled file is saved

  … watch test, a document is saved

  … watch test, both sides changed

  … watch test, an error and a fix

  … watch test, an include

  wait "$pid" 2> /dev/null

When a file and a document change in one quiet period, sync cannot say which way to go. Watch must say so, do nothing, and not run again by itself, since nothing changed since (W5). When the writer puts the file back, only the document differs, and watch tangles.

# Tangling 100,000 lines of code is timed, and the time is reported.
speed() {
  local big=$work/big
  mkdir -p "$big"
  awk 'BEGIN {
    print "… :file: big.txt\n----"
    for (i = 1; i <= 1000; i++) print "… part " i
    print "----\n"
    for (i = 1; i <= 1000; i++) {
      print "… part " i " :file: big.txt\n----"
      for (j = 1; j <= 100; j++) print "    line " j " of part " i
      print "----\n"
    }
  }' > "$big/big.adoc"
  local start end
  start=$(date +%s)
  (cd "$big" && "$litmus" tangle -o out big.adoc) > /dev/null
  end=$(date +%s)
  local lines
  lines=$(wc -l < "$big/out/big.txt")

=== The self test

The self test tangles the book into a temporary directory with the Litmus it was given, and compares each file the map lists with the one in the repository. Then it builds a Litmus from the tangled directory with the Zig in `tools/zig`, runs its unit tests, and tangles the book with it into a second directory. The second set of files must equal the repository's too, and the two maps must be equal, which is the fixed point.

… self :file: test/run.sh
[source,bash]
----
# The fixed point: the book tangles to the repository, a Litmus built from that tangles it again.
self() {
  local book=doc/implementation.adoc one=$work/one two=$work/two
  (cd "$root" && "$litmus" tangle -o "$one" "$book") || fail self "the book does not tangle"
  compare_with_repo self-one "$one"
  (cd "$one" && "$root/tools/zig/zig" build test && "$root/tools/zig/zig" build) || fail self "the tangled sources do not build and pass their tests"
  (cd "$root" && "$one/zig-out/bin/litmus" tangle -o "$two" "$book") || fail self "the second Litmus does not tangle the book"
  compare_with_repo self-two "$two"
  expect_same "self (the two tangles)" "$one/.litmus" "$two/.litmus"
}

# Every file in the map of the tangle at $2 must equal the repository's file.
compare_with_repo() {
  local path
  while IFS=$'\t' read -r first path _; do
    [ "$first" = file ] || continue
    cmp -s "$2/$path" "$root/$path" || fail "$1" "$path differs from the repository"
  done < "$2/.litmus/map"
}
