== Scanning

:litmus-dir: src

A Litmus document is ordinary asciidoc or Markdown with one addition, the Litmus command. Before anything can be labeled or tangled, every line must be put in one of a few classes: is it prose, a command, the edge of a code block, code, or something Litmus never looks at?

The answer for a line depends on where it is. A line that starts with `…` is a document command in prose, an excerpt command inside a labeled block, and nothing at all inside a literal block or a comment. So the scanner is a small state machine. It sees one line at a time, remembers whether a block is open and how it will close, and returns the line's kind. It does no IO and allocates nothing.

The scanner does not know about labels. It cannot tell a labeled block from an illustration, because that depends on the lines before the block. It only reports that a code block opened, that a line is code, and that the block closed. The parser, in the next chapter, adds the meaning.

The scanner is one file. Its public parts are the kinds of line, the `Scanner` itself, and a few small functions that the parser and the commands also need.

These are the classes of line. Most are what they say. Two deserve a note.

`code` is any line inside a code block, whether or not it holds a command: inside a block, the parser decides what a command means. `skip` is a line that Litmus never reads: comment lines and blocks, literal and passthrough blocks, HTML comments (L5, M3). Keeping these apart from `prose` matters, because a label must be followed directly by its block (L2), and a comment between them is an error.

Attribute and title lines (`[source,zig]`, `.The loop`) are the only lines allowed between a label and its block, so they get kinds of their own. Markdown has neither, and never produces them.

The scanner is always in one of these states. `prose` is outside any block. `listing` and `fenced` are the two code blocks. `literal`, `comment` and `passthrough` are asciidoc blocks whose lines are ignored. `html_comment` is Markdown's.

A Litmus command is the ellipsis character (U+2026) followed by a space, after any spaces and tabs. Three full stops are not a command, and an ellipsis with no space after it is not either, so `…` in running text is safe.

`commandOf` returns the bytes before the ellipsis, which are the indent of an excerpt command (L3), and the text after it. It is used for document commands in prose, for excerpt commands in code, and by the scanner to classify lines.

/// A Litmus command line: the bytes before the ellipsis, and the text after it.
pub const Command = struct { indent: []const u8, text: []const u8 };

const ellipsis = "\u{2026} ";

/// The Litmus command a line holds, if it is one: after any spaces and tabs, the
/// ellipsis and a space.
pub fn commandOf(line: []const u8) ?Command {
    var i: usize = 0;
    while (i < line.len and (line[i] == ' ' or line[i] == '\t')) i += 1;
    if (!std.mem.startsWith(u8, line[i..], ellipsis)) return null;
    return .{ .indent = line[0..i], .text = line[i + ellipsis.len ..] };
}

Documents are cut into lines at `\n` and nowhere else (L7). A `\r` before the `\n` stays part of the line, so that tangling reproduces it. A last line with no `\n` still counts as a line, and a final `\n` does not start another one.

The lines are slices of the document's text, cut in one pass: first the newlines are counted, so that the array of lines is allocated once at its exact size.

… splitLines :file: scan.zig
[source,zig]

/// Splits a document into lines at `\n` (L7). A final line without `\n` is a line.
/// A final `\n` does not start another.
pub fn splitLines(arena: std.mem.Allocator, text: []const u8) ![]const []const u8 {
    const count = std.mem.countScalar(u8, text, '\n') + @intFromBool(text.len > 0 and text[text.len - 1] != '\n');
    const lines = try arena.alloc([]const u8, count);
    var start: usize = 0;
    for (lines) |*line| {
        const end = std.mem.indexOfScalarPos(u8, text, start, '\n') orelse text.len;
        line.* = text[start..end];
        start = end + 1;
    }
    return lines;
}
----

The scanner holds its state and what it needs to leave it. An asciidoc block closes only at a line equal to the one that opened it (so a block opened with five hyphens can hold a line of four). A Markdown fence closes at a line of the same character, at least as long.

`next` is the whole interface: give it the next line, get its kind. It dispatches to the code for the document's format.

pub const Scanner = struct {
    format: Format,
    state: State = .prose,
    /// The line that opened the current asciidoc block, which only an equal line closes.
    delim: []const u8 = "",
    /// The character and length of a Markdown fence.
    fence_char: u8 = 0,
    fence_len: usize = 0,

    pub fn init(format: Format) Scanner {
        return .{ .format = format };
    }

    /// True while a code block is open: at the end of a document, that is C6.
    pub fn inCodeBlock(self: *const Scanner) bool {
        return self.state == .listing or self.state == .fenced;
    }

    pub fn next(self: *Scanner, line: []const u8) Kind {
        return switch (self.format) {
            .asciidoc => self.nextAsciidoc(line),
            .markdown => self.nextMarkdown(line),
        };
    }

        … asciidoc, block openings
        … asciidoc, fence opening
        … asciidoc, the other lines

/// A line of at least four of `char` and nothing else.
fn isDelimiter(line: []const u8, char: u8) bool {
    if (line.len < 4) return false;
    for (line) |c| if (c != char) return false;
    return true;
}

A Markdown fence line has up to three spaces of indent, then three or more backticks or tildes. `isFence` returns the character, the length and what follows, trimmed. Indented code (four spaces) is not a code block for Litmus (M1).

… Fence :file: scan.zig
[source,zig]
----
const Fence = struct { char: u8, len: usize, rest: []const u8 };

/// A Markdown fence line: up to three spaces, then three or more backticks or tildes.
fn isFence(line: []const u8) ?Fence {
    var i: usize = 0;
    while (i < line.len and i < 3 and line[i] == ' ') i += 1;
    if (i >= line.len or (line[i] != '`' and line[i] != '~')) return null;
    const char = line[i];
    var j = i;
    while (j < line.len and line[j] == char) j += 1;
    if (j - i < 3) return null;
    return .{ .char = char, .len = j - i, .rest = std.mem.trim(u8, line[j..], " \t") };
}

/// The directory in a line `<!-- :litmus-dir: src/core -->` (M5).
pub fn markdownDir(line: []const u8) ?[]const u8 {
    const body = std.mem.trim(u8, line, " \t");
    if (!std.mem.startsWith(u8, body, "<!--") or !std.mem.endsWith(u8, body, "-->")) return null;
    const inner = std.mem.trim(u8, body[4 .. body.len - 3], " \t");
    if (!std.mem.startsWith(u8, inner, ":litmus-dir:")) return null;
    return std.mem.trim(u8, inner[":litmus-dir:".len..], " \t");
}

/// The directory in an asciidoc line `:litmus-dir: src/core` (L8).
pub fn asciidocDir(line: []const u8) []const u8 {
    return std.mem.trim(u8, line[":litmus-dir:".len..], " \t");
}

=== Tests

Every test names the rule it checks. They share one helper, which scans a document and compares the kind of every line.

`expectKinds` prints the line and both kinds when they differ, so a failure says which line was misread.

… test helpers :file: scan.zig
[source,zig]
----
fn expectKinds(format: Format, text: []const u8, expected: []const Kind) !void {
    var arena_state = std.heap.ArenaAllocator.init(std.testing.allocator);
    defer arena_state.deinit();
    const lines = try splitLines(arena_state.allocator(), text);
    try std.testing.expectEqual(expected.len, lines.len);
    var scanner = Scanner.init(format);
    for (lines, expected, 0..) |line, want, i| {
        const got = scanner.next(line);
        std.testing.expectEqual(want, got) catch |err| {
            std.debug.print("line {d} {s}: wanted {s}, got {s}\n", .{ i + 1, line, @tagName(want), @tagName(got) });
            return err;
        };
    }
}

test "splitLines (L7): \\r stays in the line, a final \\n starts no line" {
    var arena_state = std.heap.ArenaAllocator.init(std.testing.allocator);
    defer arena_state.deinit();
    const lines = try splitLines(arena_state.allocator(), "a\r\nb\n\nc");
    try std.testing.expectEqual(4, lines.len);
    try std.testing.expectEqualStrings("a\r", lines[0]);
    try std.testing.expectEqualStrings("", lines[2]);
    try std.testing.expectEqualStrings("c", lines[3]);
    try std.testing.expectEqual(0, (try splitLines(arena_state.allocator(), "")).len);
    try std.testing.expectEqual(1, (try splitLines(arena_state.allocator(), "x\n")).len);
}

test "commandOf (Terms): indent, ellipsis, space" {
