== Resolving and Checking

:litmus-dir: src

The parser sees one document at a time. But an excerpt can be labeled in one chapter and used in another, and a file can be built from blocks all over the book. The resolver looks at the whole set. It groups the blocks into files, file roots and excerpts, finds which excerpt every excerpt command stands for, and runs the checks that need the whole picture: C1 to C4 and C9.

Those checks add up to one promise. An excerpt must be used exactly once (C2, C3), and may not contain itself (C4). Then every line of every file comes from exactly one line of the document set, and every line of labeled code lands in exactly one place. That is what lets tangle run backwards some day.

Names belong to their file. Two files can each have an excerpt called `body`, and an excerpt command only finds excerpts that are labeled with its own file. A command that names an excerpt of another file is C1, and the message says where the excerpt is, since that is the likely mistake.

The resolver is one file: the types of its result, one function that does the grouping and calls the checks, and three smaller functions for the checks.

A place in the document set is a document and a line. An `Edge` is an excerpt command that found its excerpt: where the command is, and what it stands for.

An `Excerpt` collects the blocks that share a name and a file, in document order. It counts its uses, which is what C2 and C3 look at, and remembers where it was first used, for the message of C3. Its edges are the excerpts that its own blocks use, which is the graph in which C4 looks for cycles.

… Excerpt :file: resolve.zig
[source,zig]
----
pub const Excerpt = struct {
    name: []const u8,
    /// In document order.
    blocks: std.ArrayList(*const Block) = .empty,
    first_label: Where,
    uses: u32 = 0,
    first_use: Where = .{ .doc = 0, .line = 0 },
    /// The excerpts that this one's blocks use, for the search for cycles.
    edges: std.ArrayList(Edge) = .empty,
    state: enum { new, visiting, done } = .new,
};
----

A `File` has its root blocks, and its excerpts by name, and also in the order of their first label, so that diagnostics come out in a stable order. It is executable if any one of its root labels says so (L9).

The result is the list of files, in order of first appearance.

=== Grouping

`resolve` has four steps, one after another: group the blocks, find what every excerpt command stands for, report excerpts nobody uses, and look for cycles. The steps run over everything, even after a problem, so the writer gets the whole list at once.

… resolve :file: resolve.zig
[source,zig]
----
pub fn resolve(arena: Allocator, docs: []const Document, blocks: []const Block, diags: *Diagnostics) !Resolved {
    var files: std.ArrayList(File) = .empty;
    var index: std.StringHashMapUnmanaged(usize) = .empty;

    // Group the blocks. Files are pointers into a list that grows, so find them by
    // index until grouping is done.
    for (blocks) |*block| {
        const label = block.label;
        … resolve, a file for each path
        … resolve, excerpts and roots
    }

    … resolve, find the uses

    … resolve, unused excerpts

    … resolve, cycles

    return .{ .files = files.items };
}
----

Files are found by their full path, in a hash map from path to position. The first block seen for a path starts the file. The map holds positions and not pointers, because the list of files grows while it is filled.

A named block joins the excerpt of its name, which the first such block creates. Because the blocks come in reading order, an excerpt's blocks are in document order. A block with no name is part of the file root. `:executable:` on an excerpt is C9, since only a file can be executable.

Next, every excerpt command in every block, the roots first and then each excerpt's blocks, is looked up. Excerpt blocks are visited as their owner's, so the edges of the cycle search are known.

An excerpt with no uses is C2, reported at its first label. An excerpt that is used only by an unused excerpt is not reported on its own: the unused one is, and fixing that fixes both.

Cycles are searched in every excerpt, not only those reachable from a root. Two excerpts that use only each other are used once each, so C2 and C3 are silent about them, but they are a cycle and tangle would never end.

=== The checks

`useAll` looks at the commands of one block. If the excerpt exists, it counts the use. The second use of an excerpt is C3, reported at the second command, and the message says where the first was, since either could be the one to remove. A command with no excerpt is C1.

… useAll :file: resolve.zig
[source,zig]
----
fn useAll(arena: Allocator, docs: []const Document, files: []const File, file: *File, block: *const Block, owner: ?*Excerpt, diags: *Diagnostics) !void {
    for (block.commands) |command| {
        const at: Where = .{ .doc = block.label.doc, .line = block.first_line + command.index };
        const target = file.excerpts.get(command.name) orelse {
            try reportMissing(diags, docs, files, file, command.name, at);
            continue;
        };
        if (target.uses > 0) {
            const first = target.first_use;
            try diags.add(at.doc, at.line, "C3: the excerpt \"{s}\" is already used at {s}:{d}", .{ command.name, docs[first.doc].path, first.line });
        } else {
            target.first_use = at;
        }
        target.uses += 1;
        if (owner) |o| try o.edges.append(arena, .{ .target = target, .at = at });
    }
}
----

For C1, the message is better when the writer has probably used the wrong file. So before saying that nothing is there, it looks for an excerpt of that name in the other files, and names the first one it finds.

… reportMissing :file: resolve.zig
[source,zig]
----
fn reportMissing(diags: *Diagnostics, docs: []const Document, files: []const File, file: *const File, name: []const u8, at: Where) !void {
    for (files) |other| {
        if (&other == file) continue;
        if (other.excerpts.get(name)) |excerpt| {
            const label = excerpt.first_label;
            try diags.add(at.doc, at.line, "C1: no excerpt \"{s}\" in {s}; there is one in {s}, at {s}:{d}", .{ name, file.path, other.path, docs[label.doc].path, label.line });
            return;
        }
    }
    try diags.add(at.doc, at.line, "C1: no excerpt \"{s}\" in {s}", .{ name, file.path });
}
----

Cycles are found by a depth-first search. An excerpt is _new_, _visiting_ while the search is inside it, or _done_. An edge to a visiting excerpt closes a cycle, and is reported once, at that edge, with the excerpt that holds it. Because a finished excerpt is never visited again, each cycle is reported once however many ways lead to it.

… findCycles :file: resolve.zig
[source,zig]
----
fn findCycles(arena: Allocator, docs: []const Document, file: File, excerpt: *Excerpt, diags: *Diagnostics) !void {
    if (excerpt.state != .new) return;
    excerpt.state = .visiting;
    for (excerpt.edges.items) |edge| {
        switch (edge.target.state) {
            .new => try findCycles(arena, docs, file, edge.target, diags),
            .visiting => try diags.add(edge.at.doc, edge.at.line, "C4: the excerpt \"{s}\" in {s} contains itself, through \"{s}\"", .{ edge.target.name, file.path, excerpt.name }),
            .done => {},
        }
    }
    excerpt.state = .done;
}

=== Tests

The tests parse a document from a string, resolve it, and look for the diagnostic they expect. Every check has one test that triggers it, and a case that just misses it.

`check` parses and resolves a document and returns the diagnostics and the result.

… test helpers :file: resolve.zig
[source,zig]
----
// Tests ----------------------------------------------------------------------

const t = std.testing;
const scan = @import("scan.zig");
const parse = @import("parse.zig");

const Checked = struct {
    diags: Diagnostics,
    resolved: Resolved,

    fn expect(self: Checked, line: u32, needle: []const u8) !void {
        for (self.diags.list.items) |d| {
            if (d.line == line and std.mem.indexOf(u8, d.message, needle) != null) return;
        }
        std.debug.print("no diagnostic at line {d} with \"{s}\"; have:\n", .{ line, needle });
        for (self.diags.list.items) |d| std.debug.print("  {d}: {s}\n", .{ d.line, d.message });
        return error.MissingDiagnostic;
    }

    fn expectCount(self: Checked, n: usize) !void {
        if (self.diags.list.items.len != n) {
            for (self.diags.list.items) |d| std.debug.print("  {d}: {s}\n", .{ d.line, d.message });
        }
        try t.expectEqual(n, self.diags.list.items.len);
    }
};

fn check(a: Allocator, text: []const u8) !Checked {
    var diags = Diagnostics.init(a);
    const doc: Document = .{ .path = "d.adoc", .format = .asciidoc, .lines = try scan.splitLines(a, text), .dir = "" };
    const parsed = try parse.parse(a, 0, doc, &diags);
    const docs = try a.dupe(Document, &.{doc});
    const resolved = try resolve(a, docs, parsed.blocks, &diags);
    return .{ .diags = diags, .resolved = resolved };
}
----

The first test checks the grouping: files in order of first appearance, roots, executable files, excerpts of several blocks. The rest check C1 (including the hint about another file), C2, C3 (including an excerpt used once in each of two files, which is fine), C4 (a self-cycle, a two-excerpt cycle that no root reaches) and C9.
